# RV32I 乱序超标量 IFU 规格——以 C910 微架构和流水线为蓝本

版本：v3.1，2026-09-20；按用户要求固定为无 MMU 配置。  
适用目标：仅实现 RV32I、无 MMU 的乱序、多发射超标量处理器；尽可能保留 C910 IFU 的性能设计。  
依据：`IFU_microarchitecture_spec_thinking_zh.txt`，以及本仓库 `ifu/rtl/ct_ifu_*.v` 的相关有效实现。  
版本关系：本版取代此前的顺序单发射稿及简化乱序稿；不再采用“简单 BHT+BTB、F0/F1/F2、关闭 RAS/LBUF/IPB”的方案。  
状态：待实现的设计规格，非已完成 RTL 报告；未进行本设计的仿真、综合或时序验证。

## 0. 设计原则与范围

### 0.1 核心目标

保留 C910 的 **PCGEN → IF → IP → IB → IBUF/旁路/LBUF → IDU** 主链、分级重定向和预测恢复体系；将指令组织改为固定 32 bit 的 RV32I，并与新处理器的乱序后端对接。

不能因为只实现 RV32I，就删除与 ISA 扩展无关的性能机制。L0 BTB、Bi-Mode BHT、间接目标预测、RAS、Way 预测、循环重放、预取、关键块优先回填、指令旁路和合并输出，均属于本版必须保留的设计范围。

“保留”指保留功能、流水阶段职责、主要状态与相互作用，不要求机械保留所有原始位宽。RV64 地址拼接、半字边界、压缩指令检测和向量属性应改造或删除；SRAM 封装、后端反馈及总线协议则按目标平台重新定义。

### 0.2 三种性质必须区分

- **C910 实现事实**：原文或已核对 RTL 中存在的功能，例如 3 路指令输出、2 路 PCFIFO 创建、RAS 12+6 两层组织。
- **本版设计决定**：为了 RV32I 移植明确选择的组织，例如将 IBUF 改为完整指令条目、统一边界接口为字节地址。
- **平台配置**：用户已明确不实现 MMU；本版采用 32 位物理地址取指和 PIPT I-Cache。特权架构、SoC 总线、调试能力仍独立定义，不由“无 MMU”自动推断删除。

首版以 C910 原有带宽为移植基准，不继续沿用此前假设的 4 路 IDU 输出。若后端最终要求其他宽度，再同步调整相关端口、缓冲、PCFIFO、提交与验证；不能只改一个输出数组维度。

### 0.3 基线配置

| 项目 | 本版基线 | 与 C910 的关系 |
|---|---|---|
| ISA / IALIGN | RV32I / 32 bit | 删除 C、RV64 专用和向量等扩展相关前端处理 |
| 指令地址 | 32 位物理字节地址，PC 即 PA，指令起点低两位为 0 | 外部不沿用 39 bit 半字 PC |
| PA_WIDTH | 本配置固定 32 | 无地址翻译，本版不定义更宽取指物理地址的生成方式 |
| MMU / ITLB / PTW | 不实现，无外部翻译端口 | 删除翻译、直通翻译适配层及页故障路径 |
| 物理区域属性 | IFU 内部静态 REGION_MAP 组合译码 | 替代来自 MMU 的属性输入，无请求/响应握手 |
| 取指块 | 16 B = 4 条 32 bit 指令 | 保留 128 bit 取指带宽 |
| IDU 输出 | 最多 3 条/周期 | 保留原三槽带宽和旁路/合并结构 |
| PCFIFO 创建 | 最多 2 项/周期 | 保留第二条元数据流 |
| 退休反馈 | 最多 3 条/周期，保留特殊 retire0 约束 | 不能假设所有特殊反馈都是三写口 |
| I-Cache | 64 KiB、2-way、64 B/line、512 sets、PIPT | 保留 ICACHE_64K 容量，改为物理索引及 17 bit Tag |
| IF/IP/IB | 保留原三级职责和寄存边界 | 不改成简化的单请求取指状态机 |
| L0 BTB | 16 项 | 保留 IF 级快速预测 |
| 主 BTB | 保留 512 行 × 4 存储槽的 bank 组织 | 原有效 Tag 宏为 2×512×22；RV32 字段可重排 |
| BHT | Bi-Mode；prediction 1024×64 bit，selection 128×16 bit | 保留阵列组织、22 bit 推测/提交历史和更新旁路 |
| IND BTB | 256 项，保留路径相关索引和同步读 | 原 23 bit 项的目标压缩字段需重审 |
| RAS | 12 项 TOP + 6 项 RTU 备份组织 | 必须保留，不是“18 深度单栈” |
| IBUF | 32 个完整 32 bit 指令条目 | 本版容量决定；相对原 32 半字条目增加数据容量 |
| LBUF | 16 个完整 32 bit 指令条目 | 本版容量决定；保留原循环状态机和分支记录 |
| PCFIFO 本体 | 默认 32 项，位于 IU/BJU 侧 | 原 `ct_iu_bju_pcfifo.v` 存在 entry0…31 |
| demand refill | 1 套状态机，4×128 bit WRAP | 保留关键块优先、返回转发和回填后重发 |
| IPB | 1 行预取缓冲，4×128 bit | 保留与 demand 的在途/完成复用 |

IBUF/LBUF 的“32/16 条”是本版明确的容量选择，不是将 C910 的“32/16 半字”误读为原本就能存这么多条指令。若资源受限，可选择等字节容量的 16/8 条变体，但应另记为面积折中，不能静默替换基线。

取指峰值 4 条/块不等于每周期能交付 4 条。无反压、持续命中且指令足够时，IDU 接口目标上限仍为 3 条/周期；不对未知后端宣称 3 IPC 或某个频率。

## 1. 保留、改造、删除清单

### 1.1 必须保留的性能机制

| 功能 | 保留理由 | 必须保留的配套条件 |
|---|---|---|
| IF L0 BTB 快速改向 | 提早选择下一取指路径 | 命中来源、槽位置、IP/IB 校正和错误项失效 |
| 主 BTB | 直接控制流目标及 Way 提示 | SRAM 读时序、更新缓冲、地址校验 |
| Bi-Mode BHT | 保留方向预测能力 | 选择表、方向表、VGHR/RTUGHR、BJU 校验快照 |
| IND BTB | 多目标 JALR 性能 | 推测/提交路径、同步读等待、恢复互锁 |
| RAS | 调用/返回预测 | x1/x5 识别、推测/提交状态、误预测恢复等待 |
| Way 预测 | 保留 Cache 读阵列优化 | 错误 Way 重发，不能把它当成真实 Miss |
| IBUF bypass / merge | 降低空缓冲延迟、补满输出槽 | 统一消耗掩码及原子记账 |
| LBUF | 短循环重放和减少阵列访问 | 分支/历史/PCFIFO 同步重放、维护退出 |
| 关键块优先和回填转发 | 降低需求首块等待 | 行有效性、错误令牌、返回保存和重发 |
| IPB 预取及复用 | 减少下一行 Miss 等待及重复请求 | 物理窗口/区域边界、独立 ID、错误隔离、维护排空 |
| SFP 的非向量部分 | RV32I load/store 同样可能发生推测失败 | no_spec 属性与 LSU/RTU 的反馈闭环 |
| 门控、停取、性能计数 | 保留可测量和低功耗控制 | 时钟使能不能替代真实 valid |

功能可有独立使能位用于 bring-up 和消融测试，但关闭配置不等于已完成该功能移植。

### 1.2 删除的 ISA 专属逻辑

- 所有 RVC opcode/立即数译码、16/32 bit 长度选择、半字指令边界识别。
- H0 跨块半条指令保存、与下一块高半字拼接、后半字取指异常标记。
- 仅用于压缩边界重新定位的 bry_missigned 状态和对应重发条件。
- RV64 专属指令类型识别，以及 64 位虚拟 PC 的符号扩展/特殊高位保持。
- V 指令与 vsetvli 相关识别、VL/VSEW/VLMUL、VL 预测/恢复和 SFP 的 VL/VL_RAW 路径。
- 仅服务 M/A/F/D/V 或其他未实现扩展的 split 属性/多微操作预处理。

不可支持的指令编码仍须作为原始 32 bit 字送到 IDU，并最终报告非法指令；不能在 IFU 静默吞掉，也不能把压缩编码当成两条 16 bit 指令。

### 1.3 不能误删的同名或混合逻辑

1. **ct_ifu_vector 管复位/异常入口，并非向量算术模块。** 保留 RESET/IDLE/PCLOAD 等入口职责，按目标特权控制器接线。
2. **SFP 不全是向量预测。** 保留 SF/no_spec 和适用的屏障路径，删除 VL 类别。其 RTL 中 `no_spec_hit/miss/mispred`、load/store 反馈与 RV32I 相关。
3. **固定长度仍需去头/截尾。** 块中入口、早期 taken、块内多分支和 PCFIFO 带宽限制都仍存在。
4. **split 不是一概等于压缩。** 逐项追踪产生和消费方；若后端仍需要普通 FENCE/系统串行化，就保留等价信息，不能按名称全部删除。
5. **无 MMU 不等于没有物理区域属性。** 删除翻译端口和等待，保留静态物理区域的执行许可、Cacheability 及推测安全检查；调试、Cache 维护及 IF 流水仍按既定功能实现。

## 3. 地址、指令粒度与容量转换

### 3.1 统一地址单位

模块边界语义使用字节地址 B[31:0]。为降低修改 C910 的风险，内部可暂用半字地址适配 `P=B[31:1]`，此时 RV32I 合法 PC 要满足 `P[0]=0`；或逐模块改为字地址 Q=B[31:2]。同一信号不得混用三种单位。

```text
字节 PC：32 bit；+4 为下一条指令；+16 为下一取指块
半字 P：31 bit；+2 为下一条指令；低 1 bit 必须为 0
字地址 Q：30 bit；+1 为下一条指令
normal_next_block = (B & 32'hffff_fff0) + 16
slot_pc[j] = (B & 32'hffff_fff0) + 4*j，j=0..3
```

迁移原则：先保证原查询端、训练端、PCFIFO 与恢复端使用相同地址变换，再优化固定零位。禁止全仓库将 `[PC_WIDTH-2:0]` 机械替换成 `[30:0]` 而不检查其实际是字节、半字还是目标低位。

RV32 的地址加法按模 2^32 处理。本配置 PC 和 PA 均为 32 位，PC 直接提供物理地址；物理 Tag 和总线地址据此定义，不生成虚拟地址、页号或翻译请求。

### 3.2 四槽固定指令组织

将原 H1…H8 的半字流改为 W0…W3 的 word 流。入口 mask 由 `B[3:2]` 得到，预测截尾 mask 由被选控制流的位置得到，异常/pc_oper/no_spec/预测信息与指令数据使用同一 mask。

正常 4 B 对齐的指令不会跨 16 B 块或 64 B 行，因此无需 H0 或 high-halfword-exception。连续指令流仍会跨块、行和物理区域边界，须处理 Miss、预取边界及区域许可；本配置没有翻译等待。

### 3.3 预码

保留“回填生成 Precode、IP 根据真实 opcode 校验”的两级结构。本版建议仍为每块 32 bit 预码，改成 4×8 bit，分别表示：condbr、JAL、JALR、call_hint、return_hint、FENCE、load、store。

这是 RV32I 的新字段分配，不是原 `ct_ifu_precode` 的逐位含义。向量/半字边界位被移除，PC 操作类型 AUIPC 可由 IP 直接识别。非法格式不能因为 opcode 部分匹配就生成可执行控制流；IP 必须复核 funct3 等合法条件。

## 4. PCGEN、IF、IP、IB 流水规格

### 4.1 PCGEN

保留原代码的来源优先级框架：

```text
调试入口 > 复位/异常入口 > RTU 恢复 > IU 恢复
 > ADDRGEN 校正 > IB 改向 > IP reissue > IP 改向
 > IF L0 BTB 改向 > IF reissue/保持 > 顺序块步进
```

其中调试/异常/RTU/IU 的有效性先由系统保证。若新后端存在同拍多个执行恢复，必须先按 ROB 年龄选择最老有效事件；不能用模块 mux 的固定优先级替代后端年龄仲裁。

重定向必须覆盖普通 stall。保留快速 pc_bus 与最终 PC 寄存路径的区分：源自复位/异常/RTU 的更高优先级 PC 可能通过 reissue 重新访问阵列，不能只改最终 PC 却让旧 SRAM 数据继续前进。

### 4.2 IF

并行组织 PIPT I-Cache/预测器访问与内部物理区域组合译码，选择 Cache 数据或回填转发数据，保存物理 PC、区域属性、异常、Way 预测及早期预测来源。PC 即 PA，不经过 MMU/ITLB 或直通翻译握手。

IF → IP 的普通推进要求物理区域执行许可/推测安全检查通过、数据源有效、无 cancel，且 IP 可接收。静态区域译码不引入可变时长翻译等待；拒绝取指时访问异常可作为独立有效结论继续流动，不能因没有命中数据而永久停顿。

L0 BTB 在 IF 尽早提出取指目标，但不能在 gateclk 开启时就算发生了一次预测消费。保留 short/no_stall_mask 的时序优化用途，并以最终有效改向和接受事件做功能记账。

### 4.3 IP

完成 Tag 汇总、正确 Way 数据选择、入口去头、4 路预译码、早期分支选择、BHT 预测、直接目标关联与指令属性整理。

IP 必须区分：真 Miss、Way 预测错需重发、等待正在回填的资源、多条件分支需分段、下游 IB 反压。删除的只是压缩边界专用停顿，不能将剩余几类合并成“整个 IP 无条件保持”。

**多条件分支**：保留 `masked_bry_update` 类机制，按剩余有效槽顺序处理方向预测与历史。处理后的前缀可向 IB 推进，同时禁止 IF 覆盖尚未处理的后缀。一个块含 4 条条件分支不表示每拍能完成 4 次历史依赖预测。

用 word_mask/processed_mask 代替半字掩码。每条条件分支的 VGHR 更新只能发生一次，与它的有效预测推进事件绑定；IB 反压、重发、同块后缀处理不得重复追加历史。

### 4.4 IB

保留进一步分支处理、RAS 和 IND BTB 目标选择、PCFIFO 创建、IBUF/LBUF 分发、直通旁路和合并输出。

IB 的独立反压来源至少包括：

- IBUF 剩余空间不足或 LBUF 填充/切换等待；
- PCFIFO 无可用创建空间；
- 本次有效前缀需要超过两个 pc_oper；
- IND BTB 同步读结果尚未返回；
- 误预测恢复期间遇到依赖 RAS/IND 状态的 call/return/JALR。

这些条件必须保留各自的“能否局部推进”和“哪些状态能更新”规则。IDU 停顿可以先由 IBUF 吸收，不要求所有级立即同拍停住。

### 4.5 流水寄存和取消域

普通 valid 寄存遵守 reset/cancel 优先于 hold/load；数据、PC、异常、预测快照和掩码同步保持。调试注入等特殊来源需独立声明优先级，不直接复制到正常模式。

| 改向来源 | 撤销范围 | 必须保留的较老状态 |
|---|---|---|
| IF L0 快速预测 | 更新年轻取指路径，保留产生预测的当前块 | IP/IB/IBUF 内更老指令 |
| IP 分支改向/重发 | 当前有效前缀保留，取消其年轻后缀/IF 请求 | 更老 IB/IBUF |
| IB 改向 | 保留源控制流及更老指令，取消年轻 IP/IF | 既有较老 IBUF |
| ADDRGEN 校正 | 按原寄存目标校验边界撤销年轻流 | 不得一律清掉更老 IBUF |
| IU 执行恢复 | 清 IF/IP/IB/IBUF 的年轻流，通知 LBUF 退出/恢复 | 后端按年龄保留源及其更老指令 |
| RTU 精确恢复/维护 | 清旧前端流及循环供给 | 与提交边界一致的架构状态 |

不能用一个全局 flush 线代替所有 C910 cancel 信号。局部修正也要修复与被撤销前缀不一致的推测历史，不能只更新取指 PC。

### 4.6 命中路径时序示例

周期 A 由 PCGEN/IF 发起阵列访问并译码物理区域；周期 B IF 保存数据/区域属性并送 IP；周期 C IP 校验命中、去头和选择分支并送 IB；周期 D IB 分发并可经旁路向 IDU 交付最多 3 条。不同块可重叠在不同级。

该示例描述逻辑阶段，阵列实际拍数由 SRAM 宏和时序实现确定；不存在 MMU 等待级。不能为了方便实现而退化成“等待一个块全部交付后才请求下一个块”的串行状态机。

## 5. 预译码、分支目标与 RV32I 语义

### 5.1 必需识别

保留六种条件分支、JAL、JALR、AUIPC，以及 call/return、FENCE、load/store/SFP 相关属性。AUIPC 是 pc_oper，但不改变控制流，不能错误加入 VGHR。

```text
BRANCH opcode=1100011，funct3 ∈ {000,001,100,101,110,111}
JAL    opcode=1101111
JALR   opcode=1100111，funct3=000
AUIPC  opcode=0010111

imm_b = sext32({inst[31],inst[7],inst[30:25],inst[11:8],1'b0})
imm_j = sext32({inst[31],inst[19:12],inst[20],inst[30:21],1'b0})
imm_i = sext32(inst[31:20])
branch_target = pc + imm_b
jal_target = pc + imm_j
jalr_actual_target = (rs1_actual + imm_i) & 32'hffff_fffe
link_value = pc + 4
```

ADD/ADDI 等普通指令无需新增 IFU 算术功能。JALR 的实际 rs1 由乱序执行端根据依赖获取，IFU 只能预测，不能读取未重命名的架构寄存器代替真实值。

### 5.2 IALIGN=32

预测器只允许向 4 B 对齐的目标有效改向。B/J 偏移虽然以 2 B 为单位编码，但目标 bit1=1 时不能正常取指；不得简单把 bit1 清零改成另一个地址。

条件分支只有实际 taken 且目标不对齐才在源分支上产生地址不对齐异常，not-taken 不报错。JAL 同样归因于源指令；JALR 清 bit0 后还须检查 bit1。源异常由后端记录/按序确认，不能用年轻目标处的 IFU 异常替代。

### 5.3 调用/返回

保留 x1、x5 两种 link register，不能只支持 x1。JAL rd 为 link 时 push pc+4；JALR 的 rd/rs1 关系决定 push/pop/同时 pop+push。

| JALR 的 rd 为 link | rs1 为 link | rd 与 rs1 关系 | RAS 提示动作 |
|---|---|---|---|
| 否 | 否 | 任意 | 无 |
| 否 | 是 | 不同 | pop |
| 是 | 否 | 不同 | push |
| 是 | 是 | 相同 | push |
| 是 | 是 | 不同 | 先取旧栈顶/执行 pop，再 push 当前 pc+4 |

C910 原 `preturn` 快路径还要求 imm=0。本版可保留此目标选择限制：非零偏移 JALR 走 IND BTB，不直接把 RAS 栈顶当成完整目标。RAS 提示分类与“是否可直接使用栈顶目标”应分别定义，避免删错合法 JALR 的预测能力。

## 6. 多级预测器与恢复

### 6.1 L0 BTB

保留 16 项快速表、目标/类型/块内位置和相应 Way 提示，位置信息从半字位置改为 4 个 word 槽。只有位于本次入口之后的有效候选才可决定当前块后继。

必须能处理：命中正确、错误类型、指令改写后的陈旧记录、目标错误、块内更早的实际控制流，以及同拍高优先级恢复。IP/IB/ADDRGEN 校正不能把发起改向的源指令误杀。

保留 ADDRGEN 对错误 L0 项的定向失效；不要把它改成“无条件向 L0 写入一个未经验证的目标”。同 PC 多次推测不得因停顿重复创建/更新。

### 6.2 主 BTB

保留 SRAM bank、读出锁存、更新/回填缓冲及其旁路，以及目标携带 Way 预测信息的结构。当前源码有效宏是 Tag 两个 512×22、Data 两个 512×44；旧注释中的 1024 行宏不是本次容量依据。

RV32I 移植可将 4 个存储槽明确映射到 16 B 块的 4 个 word 位置，保持 512 行和同样的读流水。一个可实现的新字段组织为：

```text
row = source_pc[12:4]，slot = source_pc[3:2]
tag = source_pc[31:13]，另有 valid
target = 完整 32 bit 字节地址，way_hint = 2 bit
```

此映射是本版定长指令的重排方案，不声称与原 BTB hash 逐位相同。两两打包后 Tag 宏逻辑宽度为 40，Data 为 68；可选用等价宏/寄存器包装。若继续保留原压缩 target，则必须证明高位重建和跨区跳转行为，不能只截断为 20 位。

直接分支最终由真实立即数经 ADDRGEN 校验。BTB 假命中允许产生可恢复推测，但绝不能改变指令真实语义。

### 6.3 Bi-Mode BHT：保留算法，区分三类状态

必须保留 prediction/selection 两类阵列、两组方向选择、22 bit VGHR、22 bit RTUGHR、4 项更新缓冲与查询旁路。

1. **推测历史 VGHR**：按前端实际接纳的条件分支预测结果推进；LBUF active 时使用循环路径，屏蔽普通 IP 对同一事件的更新。
2. **提交历史 RTUGHR**：按 retire0→retire1→retire2 的程序顺序，追加本拍实际提交的 0/1/2/3 个条件分支真值。
3. **方向/选择表训练**：原 C910 接收 BJU 的校验结果和保存的预测快照，并经过写缓冲/旁路更新；不能把它改述为“所有 BHT 状态只在退休时写”。

`chk_idx[24:0]` 原含 `{预测计数器低位, 选择计数器[1:0], 分支前GHR[21:0]}`，预测方向另带。保留这些信息与具体分支动态实例的绑定。

原方向表行 hash 中的历史折叠，例如 `{GHR[13:10],GHR[9:4]^GHR[21:16]}`，应连同子项选择、selection PC 索引和写旁路一起移植。PC 输入先经过统一地址适配；查询/训练各自使用不同的地址单位会造成系统性错误预测。

选择表的 Bi-Mode 更新抑制、饱和条件及旁路优先级以 `ct_ifu_bht.v` 的有效逻辑为蓝本，不简化为两个无条件同时更新的普通计数器。验证须比对完整算法输出，而不是只检查 counter 在 0..3。

### 6.4 BHT 的恢复和更新资源

IU 恢复时：条件分支恢复到“该分支前的校验 GHR + 真实方向”；非条件控制流恢复到其对应前缀 GHR。RTU 全恢复使用提交边界的历史。

必须定义 RTU flush 与同拍退休的边界：恢复值是否包含本拍实际已提交的较老分支，由后端与 IFU 一致决定。不能直接复制旧寄存器优先级而把新后端同拍已提交事件漏掉。

BJU 校验每个有效动态分支只送一次；多执行单元同时返回时由后端排队/仲裁。4 项表写缓冲满时可以采用原类“丢弃本次性能训练”的策略并计数，不得丢失实际恢复事件或提交历史。若选择无损训练，则必须增加 ready/队列及避免等待环，作为明确的接口变更。

已经发生的错误路径方向表污染可以作为性能状态容忍，不要求 SRAM 全表回滚；但 VGHR、PCFIFO 关联和 RAS/路径恢复必须正确。失效代际的迟到 BJU 响应不得再触发恢复或错误配对。

### 6.5 IND BTB

保留 256 项表、路径历史与 GHR 组合索引、推测/提交路径寄存器。保留 IB 同步读等待状态，不把同步 RAM 改述成当拍组合命中。

原索引将四段路径低位与 GHR[7:0] 组合；按相同事件顺序维护查询和训练路径。原实现 RTU 的 JALR 误预测训练目标主要来自 retire0，需遵守第 9 节特殊退休限制。

原 23 bit 项含 valid、特权信息和目标低位。RV32 目标建议直接保存完整 32 bit 地址，另加 valid/上下文位；保持表深度与读时序，避免未验证的高位拼接。无特权切换的平台可以简化上下文字段，不得据此删除间接预测器。

### 6.6 RAS 与 C910 式延迟恢复

保留 12 个 TOP entry、6 个 RTU 备份 entry、相应指针/状态、空栈回退、溢出处理和同时 push/pop。两部分不是可以简单相加的 18 深度栈。

推测 push/pop 绑定于 IB 有效接纳 call/return 的事件，stall 不重复。实际使用的 return 目标必须与 PCFIFO 记录一致。空栈或不可用状态回退其他目标预测/后端校验，不得输出未初始化地址。

本版首选保留源码的恢复协议：

- IU 提前误预测恢复后，后端维持 `mispred_stall` 类状态；IB 遇到 call/return/间接分支时等待。
- RAS/IND 的提交侧状态继续按较老真实退休事件推进。
- 当相应误预测源到达规定退休/恢复点，RTU 发 retire0_mispred 或全 flush，按源码恢复 TOP/path，并解除等待。

这是一个完整的后端集成契约。不能只复制 RAS 存储而漏掉 `mispred_stall`，也不能让解除等待依赖一条已经被较老恢复杀死、永远不会退休的源指令。多个恢复须由后端跟踪最新仍有效的恢复边界；更老全恢复可直接替代并结束旧等待。

若不接受等待至退休的性能限制，可另行实现即时 RAS/path 检查点及内容撤销。这是增强变体，不应在没有检查点的情况下宣称“在 IU 恢复拍简单复制提交栈就完成恢复”。

### 6.7 前端局部校正和历史归属

IF 的 L0 预测只提出早期路径，不能与 IP 的真实条件分支历史推进重复计数。IP 分段、IB 校正和 ADDRGEN 注册校正需要保存与其源分支对应的历史快照/处理掩码。

较老 IB 改向与年轻 IP 历史推进同拍时，较老取消优先，年轻推进不得留下。局部校正必须恢复到保留下来的程序前缀，再按该前缀的预测结果继续，不得把被丢弃后缀的历史留在 VGHR 中。

## 7. IBUF、旁路、合并输出和 LBUF

### 7.1 IBUF

从 32 个 16 bit 条目改为 32 个完整指令条目，保存 opcode、指令 PC/位置、异常、no_spec、FENCE、预测/PCFIFO 关联属性。每拍最多吸收 4 条，最多输出 3 条；容量检查必须按本拍实际剩余入队数计算。

保留三条输出路径：IBUF 普通出队、空 IBUF 时 IB bypass、IBUF 不足 3 条时用当前 IB 补足。所有路径共享一个连续前缀消耗决定，不允许旁路出去的指令又入队。

```text
候选流 = 较老 IBUF 指令 + 当前已获准 IB 前缀
delivered = IDU 实际接收的连续最老前缀（最多 3）
ibuf_pop = delivered 中来自 IBUF 的条数
ib_bypass = delivered 中来自当前 IB 的条数
ibuf_push = 当前 IB 获准进入缓冲的条数 - ib_bypass
count_next = count - ibuf_pop + ibuf_push
```

IB 原子接受还须检查剩余入队空间和 PCFIFO 配额。不能只因为能 bypass 两条，就把无处存放的另两条丢掉。全局 flush 优先于所有 pop/push；局部改向保留更老 IBUF。

### 7.2 IDU 接收协议

保留三槽候选输出及普通/旁路反压的逻辑职责。若原样复用 C910 stall 接口，必须同时复用它们的集成约束，不能把 `id_stall/id_bypass_stall/mispred_stall` 当作任意独立输入。

对新后端，建议用适配器对外提供 `valid_num=0..3` 和 `accept_num=0..valid_num`，只接受连续前缀；内部生成符合原流水要求的 stall、普通出队和 bypass 控制。适配器不能导致功能上只能整组 3 条接收或把部分接收误计为全组接收。

输出每槽至少包含 `inst[31:0]`、`pc[31:0]` 或经证明等价的 PC 编码、fault 信息、pc_oper/type、no_spec、fence，以及 PCFIFO token（若有）。本版建议先传完整 PC，保留 PCFIFO 存预测检查信息；以后再压缩 PC，避免错误的高位重建影响精确异常。

### 7.3 LBUF

必须保留 IDLE、FILL、FRONT_BRANCH、CACHE、ACTIVE、FRONT_FILL、FRONT_CACHE 等状态职责，改写为完整指令粒度。保留循环识别、记录、前向分支体处理和条件不满足退出；不声称支持任意循环形态。

进入 ACTIVE 前，旧 IBUF 必须排空且无指令失效操作，防止普通路径与循环路径乱序。ACTIVE 下减少/停止不必要的 Cache 访问，但仍需要：

- 按当前迭代产生分支方向和历史；
- 为当前动态 PC 操作创建 PCFIFO 信息；
- 接收 IDU/PCFIFO 反压；
- 响应循环退出、IU 误预测、RTU flush 和 Cache 维护。

不可重复使用上一迭代的 GHR/PCFIFO 动态记录。原 LBUF 的单路 PCFIFO 创建选择也必须保留相应重放节拍限制，不能因总输出有 3 槽就一次交付超过其元数据能力的控制流。

### 7.4 SFP

保留原约 12 项结构的 SF 与适用 BAR 预测，移除向量 VL/VL_RAW 状态、输入和输出。SF 对 RV32I load/store 的 no_spec 提示，需要后端 LSU/RTU 的命中、漏预测、误预测反馈。

no_spec 是后端调度/推测约束提示，不能替代真实内存依赖检查或 FENCE 正确性。若目标 LSU 完全不进行相关推测，允许通过配置关闭 SF，但必须写明关闭的是后端不使用的性能闭环，而不是“RV32I 不需要 SFP”。

## 8. PCFIFO 双流配对

### 8.1 创建对象与字段

保留 `ct_ifu_pcfifo_if` 每拍最多两项创建，PCFIFO 本体在 IU/BJU。pc_oper 至少包括条件分支、JAL、JALR、AUIPC；**超过两项 pc_oper 与超过一个条件分支是两种不同资源限制**。

每项语义上至少记录：源 PC、预测目标/后继、操作类型、dst_vld、方向预测、chk_idx/GHR、JALR 预测状态、动态 token。对于 AUIPC，记录完整源 PC但不更新分支历史；不能漏掉其 PC 数据需求。

源和目标统一为 32 bit 字节地址；原代码中有的字段拼 `{P,1'b0}`、有的已经是字节 target，必须逐个转换。

### 8.2 原子配对和超配额

对本次 IB 获准前缀：先计算 pc_oper 数量和 PCFIFO 可创建数量，最多创建 2 项，再决定被消费的指令 mask。指令进入 IBUF 或 bypass 后必须已经绑定相应记录；PCFIFO full 时不能只压住其中一个流。

一个块为 `AUIPC0, AUIPC1, AUIPC2, ADDI3` 时，即使没有任何条件分支，也要分两次处理 PCFIFO 创建，不能静默丢第三项。保留 more_than_two、over_mask/已处理 mask 和后缀继续机制。

PCFIFO 创建可能早于指令被 IDU 接收，因此 token 生命周期必须跨 IBUF 驻留。可用显式 slot+generation token，或严格等价的按序分配/读取协议；无论哪种，都禁止相同 PC 动态实例串项。

### 8.3 与 ROB 的绑定和释放

后端重命名/ROB 分配时把指令与已创建 PCFIFO 记录关联。执行校验必须使用该次预测的快照，不能执行时重新查 BHT/BTB。

已解决但未退休的较年轻记录在较老分支恢复时可被丢弃；在途源身份必须用 ROB 环形年龄及代际判断。不能简单比较 ROB index 数值，也不能只比较 PC。

记录在不再被指令、执行反馈、恢复或提交训练引用后才释放。局部前端取消和全局恢复要同步回收对应年轻预建记录；不能留下只存在于 PCFIFO 而不再有指令的孤儿项。

## 9. 乱序后端、执行校验和退休接口

### 9.1 执行校验

多个未决分支可同时存在并乱序完成。每次结果带有效动态身份，后端筛除已被更老事件取消的结果，再比较真实下一 PC 与保存预测 NPC。

```text
condbr: actual_npc = taken ? pc+imm_b : pc+4
JAL:    actual_npc = pc+imm_j
JALR:   actual_npc = (rs1_actual+imm_i) & ~1
mispredict = source_live && !source_exception && actual_npc != saved_pred_npc
```

同拍多个有效恢复选最老；年轻先恢复、较老后来再恢复是允许场景。IFU 清自身年轻流水，后端同时恢复 rename、ROB、发射队列和 LSQ 等状态。

### 9.2 不能统一成一种“提交训练端口”

| 通路 | 来源/顺序 | 用途 |
|---|---|---|
| BJU check | 有效执行校验，最多按接口带宽逐条送出 | BHT 方向/选择训练、IU 恢复所需快照 |
| retire0/1/2 condbr | 实际退休的程序顺序 | 一次追加最多 3 个 RTUGHR 结果 |
| retire0/1/2 jmp | 实际退休的程序顺序 | IND 提交路径推进 |
| retire0 call/return | 原 RAS 特殊退休口 | RTU RAS 更新 |
| retire0 mispred / jmp_mispred | 特殊退休事件 | RAS/IND 恢复及相关目标训练 |
| RTU flush | 精确提交/异常边界 | 恢复提交侧历史和入口 |
| SFP feedback | LSU/RTU 有效反馈 | no_spec 性能训练 |

本版保留这一区分，而非新建一个 3 写口通用队列后声称与 C910 原实现等价。

### 9.3 特殊 retire0 约束

原 RAS/IND 的部分更新只查看 retire0。本版默认由提交控制器约束：需要该特殊口的调用/返回、相应误预测恢复事件，安排到 retire0，必要时缩短前一拍或本拍退休前缀。

不允许一条特殊指令在 retire1/2 真实提交而其 RAS/恢复事件无声丢失。若新后端要求这些事件任意 lane 同拍多条，就必须增加按程序顺序折叠的多事件适配器，并验证同拍 pop/push、路径更新和恢复边界；这属于明确的后端适配工作。

普通条件分支的 3 路 RTUGHR 更新仍保留，不应为了简化特殊口而把所有退休都降为单路。

### 9.4 必备顶层接口组

- IDU：三槽指令与实际接收/普通和旁路反压。
- IU/BJU：PCFIFO 空间与创建接收、分支校验快照/真值、执行恢复 PC、mispred_stall。
- RTU：三路实际退休属性、特殊 retire0 事件、精确 flush/入口、SFP 反馈。
- 配置/系统：预测器和 Cache 使能/失效、复位地址、维护地址/范围及完成应答。
- 无 MMU 外部接口：IFU 内部 REGION_MAP 按物理地址生成区域属性；仅通过既有 BIU 接口发物理存储请求，不新增翻译或直通适配握手。
- BIU：需求/预取读请求、ID、burst、返回 data/error/last、ready。
- 调试/性能：入口/退出取消、PC 观察、命中/误预测/停顿事件。

对 pc_oper 和恢复的正确性敏感事件必须不丢；可丢的性能训练事件要单独定义并计数，不能混在同一个 valid 中。

## 10. PIPT I-Cache 与物理区域属性

### 10.1 64 KiB、2-way 组织

保持 512 sets、64 B/line、每路每次候选读出 128 bit Data 与 32 bit Precode。每 set 保留原替换/FIFO 位职责，不擅自换成 LRU 并宣称是原设计。

```text
line_offset = B[5:0]
block_offset = B[5:4]
word_slot = B[3:2]
index = PA[14:6]              // PIPT，9 bit，512 sets
physical_tag = PA[31:15]      // 17 bit，PA_WIDTH=32
```

物理 Tag、set 和行内 offset 完整覆盖 32 位物理地址。将原含物理页号的宽 Tag 重排为 17 bit；不再保留与虚拟索引重叠的页位。容量、2-way、Way 预测和回填性能机制保留。

### 10.2 无 MMU 的物理区域检查

不实现地址翻译、ITLB、页表遍历、翻译取消或 instruction page fault；不保留 MMU 直通适配模块。物理行失效仅查 PA[14:6] 指定 set 的两个 way，并按 PA[31:15] 匹配 Tag；没有虚拟同义地址的 8 索引扫描。

物理区域属性由 IFU 内部静态 `REGION_MAP` 参数表组合译码，表项为不重叠的物理基址、长度和 `exec_allow/cacheable/bufferable/sec/spec_safe`。它不做地址转换，不需要外部请求/响应端口，也不宣称实现 PMP。ROM/RAM/MMIO 的具体地址由 SoC 内存图在集成时填入；未映射默认拒绝，不假设整个 4 GiB 空间均可执行、可缓存。

区域边界按 64 B 对齐、行内属性一致。需求和预取分别检查目标地址范围，属性在请求形成时锁存，不能在返回时用新的 PC 重新译码。`exec_allow=0` 或 `spec_safe=0` 时禁止需求/预取总线读；live demand 形成取指访问故障，纯预取直接取消。该规则也约束 Cache 命中流。非缓存但可执行且允许安全块读的区域走 16 B 单 beat 旁路。

`cacheable` 独立于 I-Cache 功能开关；`bufferable/sec` 用于原 BIU 属性编码。无安全域区分的平台将 `sec` 配置为约定常量，BIU 负责外部极性映射。保留特权/调试输入不代表需要 MMU；本版区域表是静态配置，未增加动态保护寄存器接口。

### 10.3 Way 预测

Way 预测是数据读使能/功耗优化，不是 Tag 命中结果。关闭预测时两路可读；开启时若命中未读的另一 Way，必须带正确 Way 重发当前块。

该情形不启动 demand refill，不消费错误路数据，也不更新成一次真实 Cache Miss。Tag 比较、预测 Way、数据有效与回填转发标志须逐级配对。

### 10.4 阵列竞争

复位/失效、回填写、IPB 查 Tag、调试/软件读与普通取指共享阵列。保留原互斥选择及 one-hot-or-zero 检查，并明确谁阻止冲突请求；不能保留 default=X 的 mux 却去掉使请求互斥的控制。

Precode 与 Data 同时回填、失效和选择 Way。部分行不得因 Data 已写或需求块可用就提前置全行 valid。

## 11. Demand 回填、转发和重发

### 11.1 请求格式与关键块优先

保留单 demand 状态机，Cacheable 为 4 个 128 bit beat、64 B WRAP，首地址为需求 PC 所在的 16 B 块：

```text
start = PA & ~0xF
k0 = PA[5:4]
beat k 地址 = line_base + 16*((k0+k) mod 4)，k=0..3
```

例如需求 0x1034：返回块顺序为 0x1030、0x1000、0x1010、0x1020。首块中去掉 0x1030 指令，从 0x1034 开始供给。不能沿用压缩例子的 0x1036，也不能退化成必须行首先返回。

Cache 关闭或区域不可分配时保留单 beat 128 bit 取块模式，不写 Cache。平台必须保证该 16 B 块可执行且推测读取无副作用；若只允许精确 word 访问，需在总线适配器实现窄读变体，不能对设备 MMIO 强行读整块。

### 11.2 状态与两种生命周期

保留 IDLE、REQ、WFD1…4、INV_WFD1…4、维护互锁 CTC_INV 的功能职责。原历史注释中的 WFG 不作为当前必备有效状态。

分别维护：

1. 存储事务是否仍在途、必须收尾；
2. 它能否给当前 live 指令流供数据；
3. 能否继续合法写 Cache。

普通改向允许某些旧事务继续把无错行填入 Cache，但禁止旧块作为新路径指令消费。错误/维护使安装无效时，继续排空剩余 beat。不能统一写成“一有重定向立即停止全部返回”，也不能将“busy”误当“当前取指必须等待它的数据”。

原实现 WFD1 与 WFD2…4 对改向的转移不相同；若复用 RTL，保持有效代码优先级并验证 data/error/chgflw 同拍，不能仅照状态名称重写。

### 11.3 行原子发布

第一次覆盖 victim 数据前清其 valid；中间 beat 写 Data/Precode；末 beat 仅在本次整行无错且安装未被维护取消时写 Tag、置 valid、更新替换状态。

首个需求块可以通过独立转发路径提前进入 IF/IP，**不等待整行 valid**。因此整行安装完成和某条指令已交付是不同事件。后续其他 beat 出错不能事后把已经正确取得的较老指令改成异常；失败行保持无效，后续实际需求按其位置报告/重取。

### 11.4 转发保存与重发

返回 beat 可能遇到 IP/IB 反压。必须依靠返回暂存、Cache 中合法保留的数据及 reissue 机制保证之后可重新取得，不能要求总线数据只停留一拍就一定被消费。

建议明确记录当前块的 live 关联、可用数据/错误和已消费 word mask。已通过转发完成的前缀不能在行末 reissue 后重复交付；未消费后缀不能因块 PC 已推进而丢失。

回填末拍/错误/单 beat 完成后，保留经过寄存的 reissue 让下一 PC 重新访问 SRAM。不能将回填期间没有真实读到的 SRAM 输出直接当作新块。

### 11.5 错误精度

128 bit beat 错误作用于该取指块。只对当前有效路径中实际需求该块的最早指令位置生成异常，不能把纯预取错误或另一块错误归到已经成功交付的 PC。

一条 RV32I 指令没有后半字跨块异常，故异常元数据只需起点 PC 和访问/权限原因。旧路径返回错误继续收尾，不产生当前新路径的精确异常。

## 12. IPB 预取及 demand 复用

### 12.1 触发与边界

保留原“demand 获授权后，条件允许时触发下一行预取”的时机，不改成每次命中无条件发预取。下一行先查 Tag，已经存在则不重复请求。

基线暂保留不跨当前物理 4 KiB 地址窗口的保守预取限制，以减少对原 IPB 边界控制的改动；它不代表虚拟页，也不需要翻译。下一行必须独立通过 REGION_MAP 的整行检查，要求可执行、可缓存且推测安全。后续可放宽 4 KiB 限制，但仍须检查目标物理区域及地址加法溢出，不得向 MMIO 或未映射区域预取。

### 12.2 ID 和独立状态

demand 使用 ID=0，prefetch 使用 ID=1。总线仲裁 demand 优先；两个 ID 的返回可交织，必须按 ID 分类到正确状态机/缓冲，不将另一 ID 的 beat 推进本事务计数。

保留请求机 IDLE/CACHE/CMP/PF_REQ/PF0…3/INV，及回放机 PF_IDLE/PF_VLD/PF_GRNT/PF_WB0…3 的功能分离。IPB 是一行缓冲，不是第二套任意索引命中的 I-Cache，也不是多个 demand MSHR。

### 12.3 demand 命中预取

需求命中同一在途预取行时等待该结果，命中已完整预取行时从 IPB 内部 grant/replay 供应 L1 refill，不能重复向外请求同一行。

回放按 demand 的行内 16 B offset 从关键块开始，以 WRAP 顺序送给 refill。内部 replay 也必须经过普通 Data/Precode 写入、错误/安装与取指推进约束。

若纯预取发生错误，清其有效性并按协议排空；之后匹配 demand 不得无限等待一个永远不会变成 PF_VLD 的缓冲。可转为正式 demand 重取；错误只有成为对应 live demand 的失败结论时才送精确异常。

### 12.4 维护与总线协议

维护要清待用 IPB 行、阻止新预取，并排空/标记已授予预取，避免失效后回放旧代码。

C910 IFU–BIU 的 req/grant 支持特定的“未 grant 撤销”语义；不能直接将它视作 AXI ARVALID。若连接 AXI，适配器在接受内部请求时锁定描述符，一旦呈现 ARVALID 即保持到 ARREADY，取消只把已呈现/已接受事务标为不再供 live 流，仍收尾。

需求/预取 ID 不能在该 ID 的旧响应全部完成前复用。即使有限 epoch 回绕或新路径 PC 恰好相同，也不能把旧响应当新请求。

## 13. 维护、异常、入口与低功耗

### 13.1 Cache 和预测器维护

保留 Cache 全失效、按物理地址/索引的行失效及平台需要的软件读。PIPT 行失效检查单个 set 的两个 way；删除虚拟别名扫描，不更改完成事件的含义。软件读 Tag 布局同步改为 17 bit Tag、1 bit valid 和 1 bit 替换信息，详见接口表。

维护期间禁止产生新的冲突 refill/install，确保维护完成后旧回填、IPB 或 LBUF 不再提供旧代码。允许保留 CTC_INV 暂停返回的互锁，但必须证明完成路径不反过来等待被自己阻塞的返回，防止死锁。

BHT、BTB、IND BTB、L0/RAS/SFP 的失效/复位分别完成；不能把 icache_inv_done 当成所有预测状态已恢复。

### 13.2 取指异常与精确提交

物理区域拒绝和总线取指错误均形成 instruction-access-fault，并以指令令牌传播；本配置不产生 instruction-page-fault（cause=12）。异常不依赖 Cache 命中。opcode 占位可以使用确定的 32 bit 值，但 fault_valid 优先于正常执行，不能将令牌当 NOP 提交。

同组异常前面的较老有效指令可以交付；异常后的年轻槽截断。允许停止进一步取指直至恢复，但必须保证较老分支能执行/退休并撤销错误路径异常，不能让异常等待阻塞整个后端进度。

精确异常在 ROB/提交端按年龄确认。已经送入 IDU 的错误路径异常，也须由更老恢复取消。

### 13.3 vector/入口与 ISA 范围

保留复位初始化等待、入口 PCLOAD 和必要的异常入口选择，但目标地址来源由新系统控制器定义。`ct_ifu_vector` 不因没有 V 扩展而删除。

普通 FENCE 属于 RV32I，保留屏障识别与后端排序协作。FENCE.I 属于 Zifencei，不因保留 I-Cache 维护硬件就自动宣称实现该扩展。

若启用 FENCE.I，后端先保证较老 store 对取指可见、清年轻后端流，再执行前端失效并从后继恢复。清 I-Cache 不等于将 D-Cache 脏代码自动写回。

### 13.4 复位和低功耗

初始化至少覆盖有效位、预测表要求的初态、GHR/path/RAS、缓冲指针和控制状态，不要求 Data RAM 全清。RESET 等待失效完成时，失效控制本身仍须运行。

保留 no_op 的事务空闲语义：需求回填和预取事务空闲，不等于 IBUF 空，更不等于 ROB 全退休。IDU 长停顿时停止无意义新 Miss，以免前端永远无法报告空闲。

门控提示可宽于真实功能使能；所有功能推进仍由 valid/accept 控制。总线还有在途事务时，不能关掉唯一能够排空它的时钟域。

## 15. 关键端到端例子

### 15.1 三槽输出与四条取指

一个块含 4 条普通 RV32I 指令。IBUF 空且 IDU 可接收时，前三条旁路，第四条入 IBUF；下一周期可用这一条与新 IB 中的两条合并输出。旁路 mask 与入队 mask 不重叠，下一块剩余指令继续缓冲。

### 15.2 一个块多个条件分支

`ADDI0, B1, ADDI2, B3`：先处理 B1 的方向与历史；B1 预测不跳后保留 B3 所在后缀并继续处理，B3 使用正确的更新后历史。B1 taken 则截掉 B3；已截掉的 B3 不推进 VGHR，也不创建 PCFIFO。

### 15.3 PCFIFO 超带宽但无条件分支

`AUIPC0, AUIPC1, AUIPC2, ADDI3`：创建带宽为两项，分段生成剩余记录。不能因为 BHT 没有冲突就将整个块一次性作为“所有元数据已就绪”推进。

### 15.4 Way 错误

IF 只读 way0，IP Tag 实际命中 way1：取消错误数据，重发正确 Way。观察到 reissue，但不新发 demand 总线 Miss。

### 15.5 首块提前返回

需求 PC=0x1034，首 beat 为 0x1030。数据有效且当前流匹配时可先交付 0x1034 起的指令；其余三个 beat 继续回填，整行直到最后才 valid。反压时保存/重发，不能重复已交付前缀。

### 15.6 预测恢复期间的返回

IU 发现误预测，立即重定向并恢复 GHR，设置恢复等待。正确路径可继续普通取指，但 IB 遇到需要尚未恢复 RAS/IND 的操作时停顿；误预测源按规定退休后 RTU 修复相应状态并解除等待。若更老恢复杀掉该源，后端改用新的有效恢复边界而非无限等待旧源退休。

### 15.7 LBUF 迭代

循环记录完成后等旧 IBUF 为空再 ACTIVE。每次重放产生新的动态分支历史/PCFIFO 记录，不能把第一次迭代的 chk_idx 原样当成后续迭代快照。循环退出/误预测/维护恢复正常取指。

### 15.8 预取复用

IPB 正在取下一行，需求转到该行：不再重复发 ID0 同行请求。预取完成后按需求 offset 从缓冲回放到 refill；若预取失败，按定义转需求重试/故障，不能卡在等待有效预取的状态。

### 16.1 功能覆盖

### 16.2 核心不变量

1. 被 IDU 实际接收的 opcode、PC、异常和预测关联属于同一动态指令。
2. 消费前缀连续；旁路、merge、入队掩码互不重叠且覆盖所有保留指令。
3. 同一条件分支只在规定推进点更新一次推测历史；被截掉/取消后缀不更新。
4. 每个 pc_oper 恰有一项匹配 PCFIFO 记录，PCFIFO 满或创建超带宽时不单边推进。
5. 本地预测校正保留较老 IBUF；后端全恢复清除所有 IFU 年轻流。
6. 方向表性能污染与精确历史/恢复状态分开；无效执行响应不能改变当前恢复边界。
7. Cache Tag 命中但未读正确 Way 时不消费错误路、不发无意义 Miss。
8. 行 valid 只在完整无错且未被维护取消的安装完成时发布。
9. 提前转发不等于整行完成，也不等于 IDU 已接收；重发不重复交付。
10. 已授予或被外部协议锁定的事务必须收尾；旧路径错误不成为新路径异常。
11. 预取与 demand 身份独立；匹配复用既不重复取数，也不丢完成/错误结论。
12. LBUF 动态元数据每迭代重新形成，active 时普通路径不重复更新历史。
13. 维护完成后 Cache/IPB/LBUF/流水/预测更新中不存在能复活旧代码的来源。
14. 在总线最终响应、后端最终解除阻塞的前提下系统继续推进；无 MMU 翻译依赖。

### 16.3 验证方法

模块级使用地址唯一字节模式、随机 grant/返回插空、随机 IDU 反压及同拍事件注入。预测器以 C910 相应有效算法作参考，针对 RV32 地址/槽重排建立映射检查。

CPU 级只把真实提交指令/精确异常与 RV32I 参考执行器比对；错误路径曾被取指或交付 IDU 并不自动是功能错误，错误路径最终提交才是错误。

性能验收分别测量 L0/BTB/BHT/IND/RAS、Way 预测、LBUF、IPB、关键块转发和 bypass/merge 的开关对照。没有证明独立功能可工作，不算“已保留原性能设计”。
