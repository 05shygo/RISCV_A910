# C910 派生与减法记录

## 1. 原代码来源

直接派生：`ct_ifu_bht.v`、`ct_ifu_bht_pre_array.v`、`ct_ifu_bht_sel_array.v`、`ct_ifu_ras.v`、`ct_ifu_ind_btb.v`、`ct_ifu_ind_btb_array.v`。文件保留原版权，新增 RV32 修改说明。生成器保留原算法状态机/组合关系，删除自动生成器指令注释并使用 `always @(*)` 避免改信号后手工敏感表遗漏。

功能重排参考：`ct_ifu_l0_btb.v/entry.v`、`ct_ifu_btb.v/tag_array.v/data_array.v`、`ct_ifu_decd_normal.v`、`ct_ifu_ipdp.v`。改造原因是 v3.1 明确采用四 word 槽、完整 32 位目标，原压缩字段和跨模块 PC 高位拼接不能直接截位移植。

`C910_delta.patch` 是六个直接派生文件的统一差异；`source_manifest.json` 保存这些原文件的哈希。手工重排模块的设计差异见下表，不宣称该 patch 覆盖完整 C910 IFU。

## 2. 保留 / 删除 / 改造

| 部分 | 保留 | 删除或改造 |
|---|---|---|
| BHT | 1024×64 prediction、128×16 selection、22 位双历史、4 项队列、更新/选择旁路、LBUF 接口 | 去 H0 条件；PC39→P31；统一查询/训练地址适配；同拍退休 flush 修复；新增局部 GHR 恢复和 drop 计数 |
| IND | 256 项、四段路径 hash、三路退休路径、retire0 目标训练、同步读+结果寄存 | 23 位压缩项→35 位完整字节目标项；新增明确结果有效与取消清除 |
| RAS | 12 TOP + 6 RTU 存储、特权标签、推测/退休分离、延迟恢复互锁 | 地址改32位字节；同步维护清空；pop+push 写旧栈顶；空栈协程仍 push；满栈 pop 不回退溢出边界；修复同拍退休恢复有效位和内容 |
| L0 | 16 项、目标/类型/方向/返回/Way、替换、ADDRGEN 定向失效 | 半字局部 Tag/目标高位重建→完整字节源/目标；word 入口和最早槽选择；原 WAIT/short 交由未来流水控制 |
| 主 BTB | 512行、4槽、两组 bank、同步读/结果锁存、一项更新缓冲、旁路/Way | 原 hash/半字目标→PC[12:4]行、[3:2]槽、[31:13]Tag；两个512×40 Tag和两个512×68 Data RAM；更新优先单端口仲裁 |
| 译码/目标 | 六种条件分支、JAL/JALR/AUIPC、x1/x5、分离 call/pop/目标可用 | 不引入 RVC/RV64/V/MMU；B/J 保留 bit1，禁止靠清 bit1 伪造对齐目标；+4 链接；32位模加 |

这些预测器原本就没有 MMU 翻译协议。无 MMU 的减法主要体现为新边界不引入翻译/页故障/虚拟地址路径；本次没有为“删 MMU”而删除合法的特权上下文标签。

## 3. BHT 算法审计说明

保留的是 `ct_ifu_bht.v` 的**有效代码**：包括 Bi-Mode 更新 admission 的饱和/选择抑制表达式、FIFO、表写关系和旁路优先级，未用教科书 bimodal 替代。

原实现的 `sel_array_check_updt_vld` 用于“是否存在训练工作”的 admission；方向表更新仍可使整笔训练进入队列。原 selection SRAM 写掩码没有为该抑制另存一个独立 FIFO 位。其选择旁路也是源码固定的 entry 优先级。初版保留这些有效行为，未静默改为另一套 Bi-Mode 算法；3000 周期原代码差分及全部阵列比较覆盖了这一点。若后续希望修正/优化这些行为，应作为独立算法变更重新评估，而不是把它混入 RV32 地址裁剪。

差分测试故意排除已明确变更的契约：H0、同拍 flush+退休、功能关闭时错误推进、LBUF/普通路径重复推进、局部恢复。它们用新接口的定向/参考模型测试验证。

## 4. RAS 初版策略与性能限制

定向仿真发现直接照搬原标量提示控制不能满足本版明确规定的 pop+push、溢出和同拍退休恢复。修改记录在生成器及 patch 中，并以 1000 周期双栈参考模型检查。

恢复有效范围采取显式六项 RTU 后缀计数，未备份的旧 TOP 内容不重新发布。正常无恢复的推测仍可保存并预测最近 12 个返回，但恢复后的深层返回命中率可能低于保留旧 TOP 幸存内容的更复杂实现。后续可以增加可证明的 TOP 内容存活标记/检查点来改善，不能在没有内容证明时只恢复指针便声称完整恢复。

该选择是初版的明确性能折中，不等于把 12+6 合并成 18 项或一个 6 项普通 RAS。也不提供 IU 当拍从提交栈即时恢复的虚假保证：IU 的 `mispred_stall` 仍由后端一直保持到有效 RTU 恢复点。
