# ===========================================================================
# 反向验证 (变异测试) 清单
#
# 用法: python3 scripts/rev_check.py [ID ...]
#
# 每条 = 一个"故意注入的错误"。驱动会: 精确替换 → 重新编译 → 跑指定用例 →
# 断言**必须失败** → 还原。抓不到的叫"幸存", 要么是真假覆盖 (要补用例),
# 要么是纵深防御 (要在报告里如实写明它不独立承重)。
#
# 格式 (严格):
#   ### <ID> <名字>
#   file:  <相对仓库根的路径>
#   tests: <空格分隔的用例名>        (branch_bench / c3_only 走指标判据)
#   note:  <这条守的是什么, 为什么承重>
#   <<<BEFORE
#   <原文, 必须与该文件里**恰好一处**逐字节相同>
#   BEFORE
#   <<<AFTER
#   <注入后的文本>
#   AFTER
#
# ⚠️ BEFORE 一旦匹配不上 (改了 RTL 或改错一个字), 驱动会响亮地失败并拒绝跑 ——
#    这是有意的: 静默跳过一条已经过期的变异, 等于假装验证过了。
# ===========================================================================

### R06 rtu_kill_arch_gate_dropped
file:  mySoC/rtu/rtl/RTU_preg.v
tests: trap
note:  陷阱那条的 kill ("分配出去但没写的 dst_preg 回 FREE") 必须门掉 ARCH 态。
       阶段 1 是恒等映射 (dst_preg == p_<lreg>, 处于 ARCH), 一条**写寄存器又陷进去**
       的指令会让 RTU_commit 拉 `ret_kill_vld`; 不门的话 p_<lreg> 被标成 FREE
       而 AMT 仍指着它 ⇒ 永久破坏 "ARCH 项数 == 32", 阶段 2 一开真重命名,
       状态表与空闲计数就对不上 (空闲计数每次冲刷按 64−arch_hi_cnt 重算, 表却不复原)。
       ⚠️ **为什么这条与众不同 (两条常规防线同时失明)**:
         * 单测台抓不到 —— 那边的 dst_preg 来自分配器, 被 kill 的必然是 ALLOC 态,
           门控是惰性的 (R01~R05 那套激励一位不变);

           这个损坏**没有任何消费者**, 功能全对。
       ⇒ 只能靠 `tb/tb_miniRV_dpi.sv` 里直接守不变量本身的那条探针
         (`[RTU 不变量] ARCH 项数 == 32`, 在 kill/冲刷后一拍做全表计数)。
       实测: 注入后 `make run TEST=trap IFU=2` 在 t=1.9us 就报
       "ARCH 项数 = 31 (应为 32)"。

    wire [2:0] kill_hit = { ret_kill_vld[2] & killable_vec[ret_dst_preg2],
                            ret_kill_vld[1] & killable_vec[ret_dst_preg1],
