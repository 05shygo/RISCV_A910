## 0. 一句话结论

**把 C910 的"三级指针 + 退休窗口 + 逐 preg 状态表 + 带门控的执行级重定向"这套骨架
搬过来**，砍掉三样东西：快速退休、指令折叠（cmplt_cnt）、96 项 5 态状态机
（换成 96×2 bit 四态 + 32×7 的架构映射表）。
**`read_entry` 中间级反过来要照抄** —— 见 D5 与 §4.2。

关键分裂：**重定向快的走执行级（只允许最旧的分支发），训练准的走退休点。**
两者的分工见 D1，是本计划承重最大的一条。

**两条硬约束**（决定了后面几乎所有取舍）：

1. **时序不许变差**：Vivado 布局布线后 **Fmax ≥ 183.9 MHz**（基线 = 现在的默认
   配置，5.6 ns 点 WNS ≥ 0 = 183.9 MHz；报告尚未入库，见 §4.2 的 ⚠️）。为此 `read_entry` 影子表项（D5）、
   `WF_ALLOC` 打拍（D2）、门控**提前一级算并锁存**（D12）都是**必做项**，不是优化项；
   §4.2 列了基线、当前瓶颈、8 条新路径与对策。⚠️ **本机没有 Vivado，这条要外跑。**
2. **省资源 —— 但排在时序后面**：省要省在**不碰关键路径**的地方。
   退休级要用的字段（`pc`/`target`/`chk`/`dst_preg`/`old_preg`）一位不砍；
   只在 CSR 退休时用的字段（约 26 bit/项）抽成单槽，省 ≈1.5 Kb（§4.3）。
   **判据是"这个字段在哪条路径上被消费"，不是"能省多少"。**
   > 📌 **2026-10-02 补充口径**：用户把这条改成"**跑分要高、关键路径要短、面积可以多花
   > 一点**"。同一份 §4.2 数据反过来读的结论是：**面积花在不在绑定路径上的地方
   > （BTB / gshare 表），重定向链上只减不加** —— 见 §4.3.0 与 D13。

目标是 **≤ 1500 行 RTL**（⚠️ **实测 2 093 行**，超出 40% —— 超的全是**注释**：
D5 影子窗口、`WF_ALLOC` 两拍、kill 的 ARCH 门控、4b 的训练口，每一处都写着
"为什么这么写"，见 §5 的说明），ROB 表项约 **124 bit** × 64 项 ≈ **7.9 Kb** 触发器
（外加 `read_entry` 影子表项 360 bit + CSR 槽 26 bit）。
📌 122 → 124 是 2026-10-02 做 4b 时加的两位（`is_jal`/`is_jalr`，见 D4）。

## 1. 目标与边界

### 1.1 本核现状里已经为乱序准备好的东西（重要）

| 已有 | 位置 | 对 RTU 的意义 |
|---|---|---|
| 前端一拍出 **3 条**指令（`idu_inst0/1/2_*`） | `ifu2/rtl/rv32ifu2_top.v` | 3 发射的取指带宽已经在了；现在核只消费 1 条（`idu_accept_num = if_accept ? 2'd1 : 0`） |
| 前端有 `rtu_flush / rtu_chgflw_vld / rtu_chgflw_pc` 三个口 | 同上 | 继续给**异常/中断/`mret`** 用（它们本来就在退休点裁决）；误预测**不走这条**，走 `iu_ifu_chgflw_*`（见 D1） |
| 前端有 `iu_chgflw_vld / iu_chgflw_pc`（现在是 EX 级误预测重定向） | `mycpu.v:897-898` | **误预测重定向留在这条**，只加门控（D12 的年龄比较 + 锁存）；`pc` 已经是 `actual_npc`，与 ifu2 约定天然对齐 |
| **预测器快照随指令走**：`idu_inst*_chk`（25 bit，含 GHR 快照 / ras_ptr / 三个归因位） | 同上 | 退休点**重训练**需要的 `chk` 有现成格式，**直接存进 ROB 表项**即可（重定向本身不需要它） |
| 重定向/训练时按 `chk` 修复 GHR/RAS 的通路 | `rv32ifu2_top.v:894` | 同一条路可复用，但**驱动源要换**：现在喂进去的是 `iu_btb_chk`（= EX 级当拍那份），重训练搬到退休点后必须由 RTU 用**表项里存的那份 chk** 驱动（见阶段 4b） |
| 提交点已经是一个明确的裁决点（WB），有完整的异常/中断/`mret` 语义 | `mycpu.v:213-232`、`CORE_DESIGN.md §4` | 退休单元要做的正是**把这个裁决点从"WB 这一级"换成"ROB 头部窗口"** |

### 1.2 退休单元负责什么

1. **ROB**：按派遣顺序建表项、按 iid 收集完成情况、按程序序退休。
2. **寄存器状态与恢复**：物理寄存器的分配/释放/回滚，架构映射表（AMT），冲刷时把映射表还给重命名级。
3. **异常与中断的裁决**：只有最旧的指令能进入陷阱；`mepc/mcause/mtval` 的产生。
4. **流水线冲刷**：误预测、异常、中断、`mret` 四类重定向 + 冲刷状态机。
5. **提交点副作用**：store 真正写内存、CSR 真正写、寄存器写回对外可见（difftest）、`instret` 计数。

### 1.3 不负责（但接口必须现在定死）

重命名、发射队列、物理寄存器堆、LSU 的乱序访存。这些是**别的计划**，
但本计划第 6 节会把它们与 RTU 的契约写清楚 —— 接口一变，RTU 就得重写。

## 3. 关键设计决策

下面每一条都是"会牵动全局、事后改代价很大"的选择。**决策 = 建议选的那条。**

### D1 重定向时机：**执行级发出（只允许最旧的未处理误预测）**，恢复靠架构映射表（不做快照）★最重要

> ⚠️ **这一节写过一版错的，已按 RTL 推翻重写。** 教训记在最后。

先给结论：**重定向从执行级发出（不由 RTU 的退休级发出），但只允许"最旧的未处理误预测"发**
——注意这个门控的**精确口径是 2026-10-02 才查清的（见下面"待核项已结案"），
不是"队头"**；恢复不靠快照，靠架构映射表（AMT）。这三件事必须同时成立才自洽
（门控口径 + 冻结窗口见 D12/D13）。

#### 从 RTL 抠出来的三条事实

**① 重定向是 IU 直连 IFU 的，根本不经 RTU。**（`iu/rtl/ct_iu_bju.v:1008`）

```verilog
assign iu_ifu_chgflw_vld = ex2_pipe2_chgflw_vld;      // → IFU pcgen 的高优先级 pcload
assign iu_ifu_chgflw_pc  = {ex2_pipe2_tar_pc_msb, ex2_pipe2_tar_pc};   // 真实目标
assign iu_ifu_chk_idx    = ex2_pipe2_chk_idx;         // 快照索引也同拍给
assign iu_yy_xx_cancel   = ex2_pipe2_chgflw_vld;      // 同时取消 IDU
```

**② 退休级那根 `chgflw` 与 mispred 无关**（`rtu/rtl/ct_rtu_retire.v:1576`）：

```verilog
retire_ifu_chgflw_vld <= retire_inst0_inst_flush;   // 只由 inst_flush 驱动
assign retire_inst0_flush   = retire_expt_vld || retire_inst0_inst_flush
                            || dbgreq_ack || retire_async_expt_vld;      // ← 没有 mispred
assign retire_inst0_mispred = retire_inst0_normal_retire && (jmp_mispred || bht_mispred);
```

`retire_inst0_inst_flush` 来自 `expt_entry` 的 `flush` 位（fence.i / cache 维护类），
**不是误预测**。退休点的 `rtu_ifu_retire0_mispred / _next_pc / _condbr_taken` 是
**重训练**信号（防错误路径污染 BHT/BTB/RAS），不是纠错路径。
一句话：**重定向快的走执行级，训练准的走退休点。**

**③ IDU 的重命名表没有回滚历史**（`idu/rtl/ct_idu_ir_rt.v:2431`）：

```verilog
assign rt_recover_updt_vld = ifu_xx_sync_reset || rtu_yy_xx_flush;
assign rt_recover_updt_preg = ifu_xx_sync_reset ? 初始映射 : rtu_idu_rt_recover_preg;
```

`rtu_yy_xx_flush`（= FLUSH_BE 单拍脉冲）到来时**整张 32×7 表被 RTU 的架构映射表覆盖**，
没有任何按分支的历史/快照。**这就是"不需要快照"的确证。**

#### 由三条事实推出的设计约束

架构映射表只反映**已退休**的映射。若某个分支在"还有比它更老的指令在飞"时就重定向，
那些更老指令的重命名会随着整表覆盖而丢失 —— 要么核会算错，要么它们必须被一起冲掉
（那就会跳过它们，同样算错）。**所以：重定向点必须等于"最旧的非退休指令"。**

C910 让这件事成立的手法是把重定向**放在最旧那条指令自己的执行级**上发，
而不是等它走完退休级：

* 它比自己走完 `read → retire → 状态机 → 发信号` 早若干拍；
* 又比"任何分支都能提前重定向"省掉整套快照。

门控在 BJU 里（`ct_iu_bju.v:752`）：

```verilog
assign bju_older_inst_vld = ex1_pipe2_inst_vld && ex1_pipe2_iid_oldest;
assign bju_chgflw_vld     = bju_mispred && !rtu_iu_flush_chgflw_mask && bju_older_inst_vld;
```

> ✅ **待核项已结案（2026-10-02，读 C910 原码 + 把两个操作数追到根）。**
> `ex1_pipe2_iid_oldest` 的生成在 `iu/rtl/ct_iu_bju.v:505-506`：
>
> ```verilog
> assign bju_rf_iid_oldest = (!bju_chgflw_vld || bju_rf_older_ex1)
>                            && (!idu_mispred_stall || bju_rf_older_mispred);
> ```
>
> 两个子条件各比一个对象，**都不是 ROB 队头**：
> * `bju_rf_older_ex1`：本拍 RF 拍发射的指令 vs `ex1_pipe2_iid`
>   —— **当前占着 EX1 的流水邻居**（`ct_iu_bju.v:485-492`）；
> * `bju_rf_older_mispred`：同一个 iid vs `mispred_iid`
>   —— **上一次已发出的重定向的 iid**，在发重定向那拍存下（`:495-499`、`:809`）。
>
> 两个比较操作数（都是 `idu_iu_rf_pipe2_iid`）一路追到 **`rob_create0_iid`，即 ROB 的
> 「分配计数器」**（`ct_rtu_rob.v:4336`），**不是退休指针**（`rob_retire0_ptr` 那条线上
> 一次都没出现）⇒ "(a) 与队头比" 明确排除。
>
> **C910 的语义 = "不比任何已发出的重定向更年轻"**，比本计划原来设想的"队头"松得多。
> 另外三条顺带查到的事实（都要照抄，见 D12）：
> * 它**在 RF（发射）拍算一次、随指令锁进 EX1，之后永不重算**（`:585`）——
>   这正是 `:483` 那句 `timing optimization: move ex1 iid age compare to rf stage`；
> * `idu_mispred_stall` / `mispred_iid` 名字带 `idu_`，但**都是 BJU 内部寄存器**
>   （`:232`/`:234`），不是 IDU 的输入端口；
> * `mispred_iid` **在冲刷时不清零**（`:805` 只清 `idu_mispred_stall`），靠
>   `!idu_mispred_stall || ...` 短路让陈旧值失效。
>
> ⇒ 影响见 D12（已按此重写）与 D13（新）。

#### 本核的落地方式

**选"执行级发出 + 门控"**，比纯退休点重定向快，又完全不需要快照：

| | 本核方案 | 纯退休点 | 任意分支提前重定向 |
|---|---|---|---|
| 恢复机制 | AMT 整表覆盖（同 C910） | 同左 | 需要 N 份快照 + 用尽停顿 |
| 重定向发出者 | **BEU（执行级）** | RTU 退休窗口 | BEU |
| 门控 | **年龄比较**（D12）："不比上一次已发出的重定向更年轻"，在 ID 拍算好锁存 | 天然成立 | 无 |
| 额外接口 | RTU/BEU 之间：`mispred_iid` + `flush_chgflw_mask` + `beu_redirect_vld`（D13） | 无 | 快照读写 |

接口（§6 的对应条目，2026-10-02 按 D12/D13 更新）：

```verilog
output       rtu_beu_flush_chgflw_mask;  // 慢路冲刷期间屏蔽再次重定向(对应 rtu_iu_flush_chgflw_mask)
input        beu_redirect_vld;           // D13: EX 发出重定向那拍, RTU 用它置"未决快路重定向"锁存位
// ⚠️ rtu_beu_retire_iid（ROB 的 pop iid）**不再是门控用的** —— 那是旧口径（队头相等）的遗留，
//    现在只当 debug 观察口，见 §6.2 的注。
```

> ⚠️ **别把 `target` 塞进 RTU 的重定向路径**：重定向 PC 由 BEU 直接送 IFU，
> 走的是 `actual_npc`（与现有 `mycpu.v:834` 的 `iu_ifu_chgflw_pc` 同源，**接口天然对齐**）。
> ROB 表项里的 `target` 只服务于**退休点重训练**（对应 C910 的 `rtu_ifu_retire0_next_pc`）。

#### 这一节写错过的教训（留给下次）

我第一版读到 `retire_inst0_mispred = retire_inst0_normal_retire && (...)` 就断定
"C910 等退休才重定向"，**只看了一根信号的门控，没去看这根信号的消费者是谁**。
`retire_inst0_mispred` 驱动的是**冲刷状态机**（清后端 + 重训练），
而真正的 IFU 重定向在同一颗芯片的另一个目录（`iu/`）里，根本不经过 `rtu/`。
**下次判断"某个动作在哪一拍发生"，要顺着信号的消费者走到尽头，而不是只看它的产生条件。**

### D2 寄存器状态与恢复：四态表 + AMT，不用 C910 的 5 态机

C910 的 `ct_rtu_pst_preg_entry.v`（577 行，例化 96 次）每个 preg 存
`lifecycle_cur_state[4:0]`（独热 5 态）+ `create_iid/create_dst_reg/create_rel_preg`
+ `iid/dst_reg/rel_preg` + 3 个 `retire_inst*_iid_match` 比较器。整个
`ct_rtu_pst_preg.v` 8 637 行。

**本核砍成四态**（不做快速退休、不做折叠，所以 `RETIRE` / `RELEASE` 两态可以合并）：

```verilog
// 每个 preg 2 bit，共 96×2 = 192 bit 状态
localparam P_FREE  = 2'd0;   // DEALLOC: 在自由池里，可被分配
localparam P_WFALLOC = 2'd1; // WF_ALLOC: 已被【选中】，等下一拍派遣确认
localparam P_ALLOC = 2'd2;   // 已分配给在途指令（推测态）
localparam P_ARCH  = 2'd3;   // 已是架构态（某个逻辑寄存器的当前映射）
```

> ⚠️ **`WF_ALLOC` 不是多余的簿记，它是给分配器打拍用的 —— 不能砍。**
> 96 位三端口优先编码器是 7 级左右的组合深度，直接串在"派遣 → 分配 →
> 更新状态"这条链上会把派遣拍压垮。C910 的做法是把它切成两拍：
> 第 1 拍只做选择（`DEALLOC → WF_ALLOC`），第 2 拍派遣确认时才落
> `WF_ALLOC → ALLOC`（`ct_rtu_pst_preg_entry.v:288-295`）。
> **时序优先的前提下，这个状态必须留着。**

转移表（**这就是全部**）：

| 事件 | 动作 |
|---|---|
| 优先编码选中 | 本拍选中的 preg：`FREE → WF_ALLOC`（**第 1 拍，只做选择**） |
| 派遣确认 | 被派遣的 preg：`WF_ALLOC → ALLOC`（第 2 拍；没派成/被冲刷则回 `FREE`） |
| 指令退休 | 新 preg：`ALLOC → ARCH`；`old_preg`（且 `old_preg >= 32`）：`ARCH → FREE` |
| **冲刷** | **所有 `ALLOC` 与 `WF_ALLOC` → `FREE`**（每个 preg 各看各的，一拍并行，不需扫描） |
| 复位 | `p0..p31 = ARCH`（x0..x31 的初始映射），`p32..p95 = FREE` |

**"冲刷时所有 ALLOC 直接回 FREE"成立的前提是"冲刷由那条分支自己的退休触发"。**
注意它**不是**在重定向当拍发生的 —— 重定向在执行级发出，而这条转移发生在几拍后
该分支退休触发的 FLUSH_BE 那一拍（完整推理见 D3.1）。
那一拍它必然已在队头、在飞指令全是比它年轻的，所以这条转移是精确的
—— **这一点靠的是"D3.1 的②"，不是靠门控有多严**（D3.1 已按 2026-10-02 的调查改口径）。

若哪天**不再要求该分支最旧**（比如允许一个更年轻的分支先重定向、而它比某条还没退休的
老指令年轻），那么到了 FLUSH_BE 那拍，那条老指令仍在飞、还占着 ALLOC 态，
这条转移就会把它的 preg 也放掉 —— 那就必须改成按 iid 比较，复杂度立刻回到 C910 水平。
⚠️ **但"重定向不必等队头"≠"允许任意分支重定向"**：C910 的门控（D12）仍然保证
**同时只有一个未处理的重定向**，所以上面那个场景不会发生。**D12/D13 与 D2 是一根绳上的两头。**

另外两处简化：
* **不需要 `retire_inst*_iid_match` 那套 96×3 的 iid 比较**：把 `dst_preg / old_preg`
  直接放进 ROB 表项（14 bit/项 = 896 bit），退休时由 ROB 广播 preg 号。
  这比 C910 的 iid 匹配**更省**（96×7 bit iid 存储 + 96×3×7 bit 比较器 vs 896 bit）。
* **不需要 96 路的 recover table 优先级仲裁**：直接维护一张 32 项的 **AMT**
  （架构映射表，32 × 7 = 224 bit，3 个写口来自 3 路退休），冲刷时整张发给重命名级
  （`rtu_ren_recover_map[223:0]`，与 C910 的 `rtu_idu_rt_recover_preg[223:0]` 同格式）。

分配用**优先编码**（C910 的 `ct_rtu_encode_96/expand_96` 就是干这个的），
按 C910 的扫描方向错开，避免 3 个口总挑同一个：

```
alloc0: p32 → p95 顺序找第一个 FREE     (低→高)
alloc1: p95 → p32 倒序找                (高→低)
alloc2: 低→高，但屏蔽掉 alloc0 已选中的
```

> ⚠️ `p0..p31` 永不进自由池。退休释放 `old_preg` 时必须判 `old_preg >= 32`，
> 否则第一次写 x1 就会把初始映射 p1 放回自由池，**这是最容易漏的一行**。

### D3 自由池用"逐 preg 状态"而不是环形 FIFO + 检查点

参考核用环形 FIFO 自由表 + 每个分支快照存一份 `head_ptr`，冲刷时把 head 拉回去。

**先说清楚：这条路本身是对的**，只是有个不容易看出来的前提 ——
FIFO 的 push（退休释放）会绕圈覆盖槽位，如果盖掉了"被 pop 走、等着回拉"的槽位就错了。
它成立的条件是 `检查点以来的 push 次数 < 检查点时刻的在途 preg 数`，
而后者恒成立：能在这期间退休的只有**比分支更老**的指令，最多 `在途数 - 1` 条
（分支自己还没退休）。**所以参考核的写法是严密的，不是隐患。**
这个不变量值得记下来：**"检查点的持有者必须一直活到冲刷发生"**。

那为什么本核不选它？因为**检查点是按分支数目算的资源**：

| | 环形 FIFO + 检查点 | 逐 preg 四态（本核选） |
|---|---|---|
| 状态 | 64×7 bit FIFO + 4~16 份检查点 | 96×2 = **192 bit** |
| 检查点代价 | 每份 = 整个 RAT(32×7) + 7 bit head ≈ 231 bit | 无 |
| 按 3 发射 64 项 ROB 配够检查点 | 需 8~16 份 ≈ **1.8~3.7 Kb** | — |
| 检查点用尽 | **停顿重命名**（参考核 `stall_o` 里那一项） | 不存在这个约束 |

> ✅ **2026-10-02 实测核实了"检查点用尽"这一行**（读参考核原码）：它只有 **4 份**检查点
> （`rename.v:97-102`，纯快照 **808 位**触发器），而
> `rename.v:144` 是
> `assign stall_o = (free_cnt < req_regs) || (req_snaps + active_snap_cnt > 4) || stall_flag_i;`
> —— **在飞未提交分支一超过 4 条就冻住整个前端**，直到最老那条提交。
> 按 ~1/6 的分支密度，**64 项 ROB 的有效窗口被卡在 20 多条指令**。
> ⇒ 当初"不选快照"的判断是对的（虽然当时的理由只是估算），而 D13 用"冻 IDU 一个窗口"
> 零面积拿到了同一个效果。
| 冲刷恢复 | 回拉一个指针 | 所有 `ALLOC → FREE`（并行，一拍） |
| 分配 | 读 FIFO 头（便宜） | 96 位优先编码 ×3（组合逻辑） |

本核选逐 preg 状态：**省掉"按分支数展开"的那一维资源，也省掉"快照用尽停顿"这条约束**。
代价是分配从"读 FIFO 头"变成 96 位优先编码 —— 这是组合逻辑，不是状态。

#### D3.1 为什么"逐 preg 状态 + `ALLOC → FREE`"是对的（写给将来改代码的人）

关键是分清**两件事发生在不同时刻**（D1 定了重定向在执行级，但 `ALLOC → FREE` 发生在
后面的 FLUSH_BE 那拍）：

1. **执行级**：最旧的分支在 EX2 发出重定向（前端立刻重启）+ 取消 IDU；
2. **退休级（几拍后）**：这条分支走到 ROB 头**正常退休**，触发冲刷状态机；
   状态机跑到 `FLUSH_BE` 时发一个单拍脉冲（`rtu_yy_xx_flush`），
   **这一拍**才做 `ALLOC → FREE` 与 RAT 整表覆盖。

到了第 2 步，这条分支**已经退休**（它自己是"正常退休 + 误预测"，不是被冲掉的那条），
所以在飞指令只剩"比它年轻的"，全都是要被冲掉的。于是：

* `ALLOC → FREE` 是精确的，既不漏放也不误放；
* RAT 用架构映射表整表覆盖也是精确的（所有非退休指令都已作废）。

**三条前提缺一不可，写 RTL 时按这个顺序自查**：
① 重定向只能由**"不比任何已发出的重定向更年轻"**的分支发出（C910 的口径，见 D12）；
② `ALLOC → FREE` 与 RAT 覆盖必须在*该分支退休之后*那一拍；③ 从执行级重定向到 FLUSH_BE
之间，**派遣必须一直冻住**（否则前端重启后新重命名的指令会被第 2 步的整表覆盖误伤）。

> ⚠️ **前提① 的口径在 2026-10-02 改过。** 旧版写的是"重定向只能由**最旧**的待解析
> 分支发出" —— 那是把 C910 的门控误读成了"队头"（结案证据见 D1 末尾）。
> 这个区别不是抠字眼，**它决定了这三条前提各自在守什么**：
> * **②并不依赖①**：冲刷由该分支**自己的退休**触发，那一刻它必然已在队头、
>   在飞指令全是比它年轻的 —— 这正是②的措辞本身。所以"AMT 整表覆盖精确"这件事
>   是靠②成立的，不是靠①；
> * **①真正保证的是③的窗口语义唯一**：不允许有多个"未处理的重定向"叠在一起，
>   否则"派遣冻到哪一拍为止"就没有唯一答案。
>
> ⇒ 改成 C910 口径后，冻结窗口仍是"从发重定向那拍到 FLUSH_BE"，但**重定向本身
> 不必等到队头** —— 这正是 D13 的收益来源。

> 反过来说：只要允许"不是最旧的指令"提前重定向，①就破了，
> 比它老的指令还活着、还占着 `ALLOC`，于是 RAT 不能整表覆盖、preg 也不能一律放回 ——
> 必须改成按 iid 比较，复杂度立刻回到 C910 的 `ct_rtu_pst_preg.v`（8 637 行）水平。

### D4 ROB 表项位域（122 bit，已含 §4.3 的省资源）

对比：C910 动态部分 40 bit（含向量/断点/debug）+ PST 里的寄存器簿记；
参考核 80 bit 静态字段放异步读 RAM。

| 字段 | 位宽 | 来源 / 用途 |
|---|---|---|
| `vld` | 1 | 表项有效 |
| `cmplt` | 1 | 执行单元回送完成 |
| `wrap` | 1 | iid 的回绕位。**表项不存完整 iid** —— `iid = {wrap, 本表项的固定索引}`，索引是常量、不需存储（照 C910 的做法）；完成总线按 7 位 iid 匹配，每项只需 6 位常量比较 + 1 位回绕比较 |
| `pc[31:0]` | 32 | 退休 PC（`mepc` / difftest / 分支训练）。**阶段一先存下来**，见 D8 |
| `target[31:0]` | 32 | **真实后继 PC**，分支在 EX 解出后写回；**退休点重训练**用它（重定向本身由 BEU 直连 IFU，不读这里） |
| `chk[24:0]` | 25 | 前端预测快照，退休时回送 IFU（修 GHR/RAS + 训练） |
| `dst_lreg[4:0]` | 5 | 退休时写 AMT |
| `dst_preg[6:0]` | 7 | 退休时 `ALLOC → ARCH`；difftest 读结果用 |
| `old_preg[6:0]` | 7 | 退休时释放（判 `>= 32`） |
| `rf_we` | 1 | 写 rd（**2026-10-01 补 A6b**：`dpi_shim.c:164` 连 `debug_wb_ena` 都比对，ena 不能用 `dst_lreg!=0` 现推） |
| `is_csr` | 1 | 本指令是 CSR 指令（字段见下表后的"CSR 槽"） |
| `is_mret` | 1 | `mret`（**2026-10-01 补**：§6.2 要输出 `rtu_mret_vld`，而 mret 没有异常包可依） |
| `is_branch` | 1 | 分支/JAL/JALR：要训练、可能要重定向 |
| `is_jal` / `is_jalr` | 2 | **2026-10-02 加（4b 落地时发现缺的）**：控制转移三分类（条件分支 = `is_branch & ~is_jal & ~is_jalr`）。BTB 训练的 `upd_cond/upd_jal/upd_jalr` 要它 —— 原来这三类是 **EX 当拍从 `ex_npc_op/ex_is_jump/ex_is_jalr` 现算**的，训练搬到退休点之后只能由表项提供 |
| `actual_taken` | 1 | 实际方向（EX 解出后写回） |
| `mispred` | 1 | 预测错误（EX 解出后写回，退休时触发 flush） |
| `is_store` | 1 | 退休时提交存储 |
| `sq_id[2:0]` | 3 | 存储队列槽号 |
| `intmask` | 1 | 阻断中断（CSR 等），见 D10 |
| — | **≈124** | 总共 64 项 ≈ 7.9 Kb 触发器 |

**CSR 槽（表项外，单个寄存器，27 bit）**：`{src1_preg[6:0], csr_addr[11:0], csr_op[2:0], csr_imm[4:0]}`。
（`csr_op` 取 **funct3 原样**、不是 2 位压缩版 —— 本核 `Control.v` 把 `csrrwi/rsri/rrci`
折进了 `RW/RS/RC`，那样一折，退休级就分不出"源是 rs1 还是 uimm5"了。A6c。）

CSR 的四个字段本来要占 **27 bit × 64 = 1.7 Kb**，而它们**只在 CSR 指令退休那一拍**
被消费（不参与判退，不在 P1 链上）。抽成单槽后表项只剩 1 位 `is_csr`：

* **省 ≈1.5 Kb**，且退休级少读 4 个 64 选 1 的字段 —— **时序是正向的**；
* 代价：**只允许一条 CSR 在途**，第二条到了停派遣（派遣逻辑加一个 `csr_inflight` 门控，
  冲刷时清掉）。CSR 在 CoreMark 里几乎不出现，实测代价 ≈ 0；
* 这条正是"省资源要在保证时序的前提下"的样板：**看字段在哪条路径上被消费，
  而不是看它能省多少**。同类字段（退休级要用的 `pc/target/chk/dst_preg/old_preg`）
  一位都不许砍。

**没有异常字段** —— 走 D9 的全局 `expt_entry`。

**判决原则（两条约束的先后）**：
**① 时序不许变差；② 在①的前提下尽量省资源。** 这两条不矛盾 ——
上一版我把它写成了"一位都不砍"，那是过头了。正确的分法是看字段**在哪条路径上被消费**：

| 字段 | 消费路径 | 判决 |
|---|---|---|
| `pc` `target` `chk` `dst_preg` `old_preg` `wrap` | **退休级**（判退、释放、训练） | **一位不砍** —— 省它们就是把组合逻辑搬进 P1 那条最长链 |
| `csr_addr/op/imm` `src1_preg` | **只在 CSR 指令退休时**用（约 1% 的指令） | **该省，见 §4.3** —— 它们不参与判退，砍掉不影响 P1 |
| `dst_lreg` `is_*` `sq_id` `intmask` | 退休级，但本来就只有 1~5 位 | 保持 |

被明确**否掉**的三个瘦身方案（记录在此，免得以后有人再提）：

| 方案 | 为什么否 |
|---|---|
| `pc` 改成 C910 的推断链（`rob_cur_pc` + `pc_offset` + 分支 `next_pc`） | 省 2 Kb，但引入一条**跨表项的加法/mux 链**（C910 那段 `read2_cur_pc_addend0` 的三选一就是新增关键路径），而且 difftest 逐条比 PC，错一位就炸。**等 §4.2 的 P1 实测有余量了再回来看这条** |
| `chk` 改成侧表（只给分支发槽位） | 省 0.7 Kb，但要加槽位分配/回收/溢出处理，**收回来的面积还不够补偿新逻辑** |
| `dst_lreg`/`old_preg` 改成"ROB 只广播 iid、PST 每项各自比对"（C910 原案） | 反而更费：96 项 × 7 位 iid 存储 + 96×3 个 7 位比较器，比 64 项 × 14 位贵得多 |

### D5 头部读：**必须用 C910 的 `read_entry` 中间级**（不做组合读）

⚠️ 这一条原来写的是"阶段一先组合读，后面再补中间级"——**按时序约束推翻**。

组合读的代价是 `64 选 1 × 3 路 × 120 bit ≈ 23 k 门`，而且它**不是孤立的一条链**，
下游紧接着就是三级联动的判退逻辑（commit1 依赖 commit0、commit2 依赖 commit0+1）
和三个 `old_preg` 释放比较 —— 整条链会变成
**"64:1 mux → 类型译码 → commit 级联 → preg 释放/AMT 写"**，
全部压在一拍里。这是新引入的最长路径，也正是本项目历次 Fmax 攻坚反复砍的那类链。

**做法（照 C910）**：3 份与表项同宽的**影子表项** `read_entry0/1/2`，
它们是寄存器、由读指针驱动：

* 退休把头部 3 项"推"进影子表项 → 判退逻辑面对的**永远是 3 个已寄存的值**，
  64:1 mux 被移出关键路径，只剩 3 选 1 的重填；
* 影子表项有三条写入路径：**移位（退休后补位）/ 补空 / 完成信号按 iid 匹配**；
* `read_entry0` 永不 pop（`ct_rtu_rob_entry.v` 里 `read_entry0_pop_en = 1'b0`）；
* 完成匹配只比 **iid 低 6 位**（退休判定才用完整的 7 位）—— 因为影子表项一定
  是当前指针附近的那几项，低 6 位足够区分，这一条也是省时序的。

**代价**：3 × 120 bit = 360 bit 额外寄存器，外加每条完成信号多 3 个比较器。
**这个面积按时序约束是必须花的。**

> ⚠️ 若改用 RAM 存静态字段（参考核的做法），**必须按异步读建模** ——
> `cpu/sim/README.md` §1 记着这个坑：按同步读建模会让取指假命中。
> 本计划默认**不用 RAM**，全部触发器，绕开这一整类问题。

### D6 不做快速退休

C910 允许"指令退休先于写回"，代价是 PST 要区分 `RETIRE`（已退休未写回）与
`RELEASE`（已释放未写回）两个状态，以及冲刷状态机里的 `WF_EMPTY`
（等"已退休未写回"的 preg 写回）。

**本核退休条件直接要求 `cmplt`（已写回）**，于是：
* 状态少一档（不需要 `RETIRE` / `RELEASE` 之分）；
* 冲刷状态机里**没有 WF_EMPTY**；
* "后端流水线是否清空"这个判据（C910 是 `pst_retire_retired_reg_wb && lsu_rtu_all_commit_data_vld`）
  **整个不需要**。

代价：退休比 C910 晚几拍。在 64 项 ROB 下这点延迟基本不影响 IPC ——
挡住退休的从来是"最慢的那条指令"，不是写回排队的最后几拍。

### D7 不做指令折叠（`cmplt_cnt`）

C910 的 `cmplt_cnt[1:0]` 是给"IDU 把多条指令折叠进一个 ROB 表项"用的。
本核 **1 条指令 = 1 个表项**，完成信号一到即完成，`ROB_CMPLT_CNT` 这两位不要。
连带 `ROB_INST_NUM`、`ROB_SPLIT`（拆分指令）也一并砍掉。

### D8 PC：阶段一每条存，推断链留作优化

C910 不存 PC，靠 `rob_cur_pc`（头部基址）+ 每条 3 bit `pc_offset` + 分支的
`next_pc` 推断（分析文档 §1 的代码）。本核**阶段一每条都存 32 bit PC**：

* difftest 逐条比对 `debug_wb_pc`，PC 错一位立刻炸 —— 存下来等于把这整类
  调试问题消灭掉；
* `mepc` / 分支训练 / debug 都要它；
* 32 bit × 64 = 2 Kb，可接受。

阶段 5 若要省面积，再按 C910 换成推断链，**验证方式现成**：
difftest 全绿 + 周期逐位不变，就证明推断链与存储等价。

### D9 异常：全局 `expt_entry`（最旧者胜），不是逐表项

C910 的 `ct_rtu_rob_expt.v` 维护**一个** 70 bit 的 `expt_entry`，
由 pipe0/2/3/4 各自的异常信息按 iid 比较更新（分析文档 §3.2 的 `expt_entry_write_sel`），
只有当**最旧的异常指令退休**时才发给 CP0。

**不采用逐表项存异常字段**（`vld+cause+tval` ≈ 37 bit × 64 = 2.4 Kb）。

本核精简版（约 45 bit）：`{vld, iid[6:0], cause[4:0], tval[31:0]}`。
* 各级（ID/EX/MEM）检出异常时，把 `{iid, cause, tval}` 打到收集口；
* 收集口按 `rtu_compare_iid`（**这个模块可以从 C910 原样搬**，74 行）判新旧，
  只保留最旧的一条；
* 冲刷时清 `vld`（错误路径上的异常要丢掉 —— 这条漏了会"凭空陷入"）；
* 退休时：若 3 条退休指令里有 iid 命中 `expt_entry.iid`，则**只退到它为止**，
  它自己不写寄存器、不写内存、不写 CSR，直接发陷阱。

`mtval` 的取值按 `CORE_DESIGN.md §4.2` 已有的口径（非法指令给指令字、
访存故障给地址、取指故障给 PC），由**检出级**装好随异常口送进来，RTU 不再重算。

### D10 CSR / store / 中断的提交点

| 副作用 | 现在（WB 提交） | 改成 |
|---|---|---|
| **store 写内存** | MEM 级就写下去（`CORE_DESIGN.md §4.4` 靠四条门控兜） | **退休时写**：地址/数据进存储队列，ROB 表项带 `sq_id`，退休才真正发出 |
| **CSR 写** | EX 级写 + `~redirect` 门控 | **退休时写**：RTU 用 `src1_preg` 读物理寄存器堆拿源操作数，算完写 CSR 并写回 rd（参考核就是这么做的） |
| **中断** | WB 提交点取，且只落在"无副作用"提交点 | **退休窗口内取**，且被 `intmask` 与"退休宽度"约束，见下 |
| **`instret` 计数** | `retire_i` 单脉冲 | **3 bit 计数**（`retire_cnt[1:0]`），golden model 同步 |

**中断的"单退休模式"**（C910 的做法，分析文档 §3.3）：中断到来时立刻
*停止新指令 commit*（`rob_int_commit_mask`），但**不影响已经提交的**，
然后在 `inst0` 退休时**把退休宽度压到 1** 并接受中断。
本核照做：`int_pending` 拉高后，`commit_mask` 只允许窗口里的 inst0 及其之前的
（用 iid 比较，与 C910 `rob_commit1/2_sync_mask` 同构），
且被中断的那条**不发 `retire` 脉冲**（`CORE_DESIGN.md §4.5` 的两边口径不能改）。

### D11 冲刷：**快慢两拍分离**，不是一条状态机包办

D1 定了重定向由 BEU 在执行级发出，所以"冲刷"其实是**两条路**，
写代码时必须分开看，混在一起是这一块最容易出的错：

| | 快路（执行级，BEU 发） | 慢路（退休级，RTU 状态机发） |
|---|---|---|
| 触发 | 最旧分支在 EX2 解析出误预测 | 该分支走到 ROB 头**正常退休** |
| 谁发 | BEU → IFU（`iu_ifu_chgflw_vld/pc/chk`） | RTU 状态机 |
| 动作 | 前端立刻从真实目标重启；`iu_yy_xx_cancel` 取消 IDU | 冲发射队列/执行级/存储队列；清 `expt_entry`；`ALLOC→FREE`；RAT 整表覆盖 |
| 延迟 | ~0（与 mispred 同拍） | 分支退休 + 状态机若干拍 |

**异常/中断/`mret` 没有快路** —— 它们本来就只在退休点裁决，直接走慢路。
所以：

```
FLUSH_IDLE --(退休窗口出现 flush 源: 异常/中断/mret/误预测退休)--> FLUSH_1
FLUSH_1    --(无条件)--> FLUSH_2      // 冲执行级/发射队列/存储队列, 清 expt_entry
FLUSH_2    --(无条件)--> FLUSH_IDLE   // ALLOC→FREE + RAT 整表覆盖 + ROB 指针复位
```

* **派遣从快路那拍起就必须冻住，一直到 FLUSH_2 结束**（见 D3.1 的前提③）——
  C910 对应的是 `start to stall IDU ID`。这条门控漏了，症状是"前端重启后刚重命名的
  几条指令被 FLUSH_2 的整表覆盖误伤"，表现为偶发算错、极难复现。
* **`rtu_beu_flush_chgflw_mask`**：慢路期间屏蔽 BEU 再次发重定向
  （对应 C910 的 `rtu_iu_flush_chgflw_mask`）。漏了会让两次重定向打架。
* 本核无快速退休（D6），所以**没有** C910 的 `WF_EMPTY` / `retire_flush_pipeline_empty`
  那一整套"等已退休未写回"的判据 —— 这是 D2/D6 换来的最大一块简化。
* ~~2 拍是上界，能不能像 C910 的 `FLUSH_FE_BE` 那样合成一拍，等阶段 1 实测再定。~~
  ✅ **2026-10-02 做了：合成一拍，冻结从 3 拍（T/T+1/T+2）压到 2 拍（T/T+1），
  实测收益 1.48%**（11,605,305 → 11,432,931）。新时间线见 §6.3 ①。
  C910 是**有条件**合（`retire_flush_pipeline_empty` 才走 `FLUSH_IS_BE`）；
  **我们无条件合** —— 顺序核里不用等排水（AMT 在退休边沿就写好了）。

**优先级**：异常/中断（同步，取最旧）> `mret` > 误预测。
同一拍里有异常又有误预测时，异常赢，误预测那条被一起冲掉（它本来就年轻），
**并且要确保它不会把前端重定向到错误的目标**（快路此时要能被慢路屏蔽掉，
这就是 `flush_chgflw_mask` 的第二个用处）。

### D12 门控：**照 C910 提前一级算好并锁存**，不要串在重定向链上

> ⚠️ **本节旧版（2026-10-01）的两个判断都反了，2026-10-02 按 C910 原码推翻重写。**
> 旧版写："判定退化成**相等比较**（`inst_iid == rtu_beu_retire_iid`，即队头），
> **不要照搬 C910 的年龄比较**"。实际是：C910 用的**就是**年龄比较，而且它比的
> **不是队头**（证据见 D1 末尾的结案）。按旧版做会同时输掉两样东西：
> * **性能更差**：分支要等到走完队头才重定向 ⇒ 前端重填不能与"等它退休"重叠，
>   而且这个窗口里派出的指令还要再冲掉重取（= 阶段 1 那 +4.66%，见 D13）；
> * **门控反而更贵**：相等比较的两个操作数里，"队头 iid"是**本拍判退算出来的**，
>   恰恰就是本节一直警告的"不要把判退链串进来"。

D1 要求给 BEU 加门控，而 BEU 的输出正是**本核历史上最敏感的那条链**
（`git log` 里有连续四轮专门砍它：`4cfc39d` 把 redirect 从 push 计数链上摘下来、
`378385d` 给重定向加 `REDIRECT_PIPE`、`5aa66f2` 把进位链移出重定向路径）。
**往这条链上串任何逻辑都要先算清楚。**

**C910 的做法（照抄）**：门控在**发射/派遣那一拍**算一次，结果**锁存**，
末级只剩"一位寄存器 AND 有效位"：

```verilog
// ct_iu_bju.v:483  注释原文: timing optimization: move ex1 iid age compare to rf stage
ex1_pipe2_iid_oldest <= bju_rf_iid_oldest;   // :585  RF 拍算, 随指令打进 EX1, 之后永不重算
// ct_iu_bju.v:752  末级
assign bju_older_inst_vld = ex1_pipe2_inst_vld && ex1_pipe2_iid_oldest;
```

⇒ **门控不加重定向链的组合深度** —— 比"7 位比较并行到达、末级多一个 AND"
还干净一档。这是 D13 能成立的前提。

**本核的落点**：iid 是在 **ID 级**分配、随指令进 ID_EX 的（§6.3 ⑪），所以

* 比较对象 = **`mispred_iid`（上一次已发出的重定向的 iid，RTU/BEU 侧的一个寄存器）**
  vs ID 级的 `disp_iid`；
* 比较在 **ID 拍**做完，结果与 iid 一起锁进 ID_EX（7 位 iid + 1 位 `is_older`）；
* 末级 `iu_ifu_chgflw_vld` 只多一个 **AND 一位寄存器**。

**两条必须照抄的附注**：

* **"非 oldest"标志一旦打入就终身有效**（`:585` 之后不再重算）。C910 靠
  "它马上会被冲掉"兜底 —— **本核必须保证同一个前提**：被判"太年轻"的那条分支
  一定在错误路径上、一定会被冲掉。这条不成立就会**静默漏掉一次重定向**。
* **`mispred_iid` 在冲刷时不清零**（`:805` 只清 `idu_mispred_stall`），靠
  `!idu_mispred_stall || ...` 短路让陈旧值失效。省一个清零口，**但顺序不能反**：
  必须先清 stall 位。（另：IID 在 `retire_rob_flush` 时会清零重来
  ——`ct_rtu_rob.v:4329`——所以年龄比较只在同一个"冲刷纪元"内有效。）

### D13 误预测路径：**照 C910 的"早重定向 + 冻 IDU 到 FLUSH_BE + 退休点不碰 IFU"** ★

> 2026-10-02 新增。**这是性能改动（D1~D12 里唯一直接冲着 CoreMark 去的一条），
> 也是阶段 1 那 +4.66% 的回收方案。** 目标由用户给定：跑分要高、关键路径要短、
> 面积可以多花一点 —— 而调查的结论恰恰是**这条不需要多花面积**。

#### 现状（对着 RTL 逐条核过，2026-10-02）

| 环节 | 现在的做法 | 问题 |
|---|---|---|
| 执行级重定向 | `iu_ifu_chgflw_vld = mispredict & ~redirect & ~rtu_beu_flush_chgflw_mask`（`mycpu.v:897`），PC = `actual_npc` | ✅ 与 C910 一致（这条没问题） |
| 派遣冻结 | `rtu_beu_flush_chgflw_mask = flushing = flush_trig \| ~idle`（`RTU_flush.v:66/76`），而 **`flush_trig` 只在退休拍产生**（`RTU_commit.v:197`） | ❌ **从执行级重定向到该分支退休之间，`rtu_disp_stall` 根本没拉高，派遣照常进行** —— 那批指令是拿**未恢复的 RAT** 改名出来的 |
| 退休拍 | `RTU_flush.v:79-81` 对前端发 `rtu_ifu_flush` + `rtu_ifu_chgflw_vld`；ifu2 里这两根是**最高优先级且会重新拉 PC**（`rv32ifu2_top.v:309-310`，`ghr_after` 还被强制清 0，`:778`） | ❌ **前端被完整重启、从同一个目标再取一次** |

一进一出 = **阶段 1 的 +4.66%**（cycles 11,137,603 → 11,656,518）。

#### C910 的做法（`ct_rtu_retire.v` 的状态机说明是原文）

| 拍 | C910 | 我们 |
|---|---|---|
| EX 解析出误预测 | ① 重定向 IFU 到真实目标；② `idu_mispred_stall <= 1`（**冻 IDU**）；③ 存 `mispred_iid` | ① ✅；② **不做**；③ 不做 |
| 该分支退休 | `retire_inst0_mispred` → **`FLUSH_IS`**（`flush IDU IS/RF … stall IDU ID`，**不碰 IFU**）→ 等 `retire_flush_pipeline_empty` → `WF_EMPTY` → `FLUSH_BE` | 冲后端 ✅ + **多做了"冲 IFU + 重定向前端"** |
| `FLUSH_BE` | PST 冲刷 + rename 恢复 + **放开** `idu_mispred_stall` | F2 同左 ✅，但冻结压根没做 |

三条关键原文（都指向"**不用快照也做得到**"，2026-10-02 有独立复核确认）：

* `FLUSH_FE`（含 `flush IFU …`）**只给 `retire_inst0_flush`（fence 类）用**；
  误预测走的是 `FLUSH_IS`（`ct_rtu_retire.v:1929-1933` 那四条转移 + `:1899-1905` 的状态说明；
  `retire_flush_fe = flush_cur_state[2]`，而 mispred 经过的 IS/WF_EMPTY/BE 三个状态 bit2 **恒 0**）；
* `rtu_ifu_flush = retire_flush_fe`（`:1965`）⇒ **误预测不冲 IFU**；
* `retire_ifu_chgflw_vld <= retire_inst0_inst_flush`（`:1576`）、
  `rtu_ifu_chgflw_vld = retire_ifu_chgflw_vld`（`:1580`）⇒ **退休点对误预测不重定向前端**。
  第三条还有一条最硬的旁证：`ct_ifu_pcgen.v` 里 grep `retire0_mispred` = **0 命中**
  —— IFU 的 PC 生成器**根本没有"退休级误预测"这个输入**。

> ⚠️ **别照抄 C910 状态机注释里的 "flush IDU ptag pool"**（`:1897` 那句）。
> 复核指出：preg 生命周期/空闲表（ptag pool = PST）在代码里是**由 BE 的
> `rtu_yy_xx_flush` 复位**的（`ct_rtu_pst_preg_entry.v:288-298` 的三个转移），
> 不是 IS 拍；`rtu_idu_flush_is` 在 `rtu/rtl` 下除了输出和 top 端口**没有任何 PST 消费端**。
> 注释与实现不符 —— 我们按 BE 的时点写。

**这也是我们比 C910 占便宜的一处**：C910 的 `FLUSH_IS → FLUSH_BE` 之间要等
`WF_EMPTY`（`retire_flush_pipeline_empty = pst_retire_retired_reg_wb &&
lsu_rtu_all_commit_data_vld`，`:1888-1889`）—— 等 **96 颗 preg 全部退休写回完成**
**且** LSU 的 store/load commit data 全部交齐，**事件驱动、拍数不定**。
**本核无快速退休（D6），永远不需要这一项** ⇒ 冻结窗口就是
`[发重定向, 该分支退休 + 2]`，比 C910 短一截。D6 当初换来的是"少两个状态"，
现在又白捡一个"冻结窗口更短"。

#### 为什么这样更好（三条，按重要性）

1. **前端重填与"等该分支退休"重叠。** 早重定向让 IFU 立刻从正确目标取指并**排在队列里**，
   冻结解除时已经有货；"等队头才重定向"把重填**串在**退休之后，两段完全串行。
2. **冻结几乎不额外花钱。** 窗口里前端刚重填、RAT 还没恢复 ⇒ **本来就没有"能正确改名的
   指令"可派**。冻的是本来就派不出去的东西。
3. **不冲 IFU、不重取 ⇒ 直接省掉 +4.66% 的主体。**

> ⚠️ **精度修正（2026-10-02 复核指出，别把话说满）：冻结生效有一个"边界拍"。**
> `idu_mispred_stall <= 1`（`ct_iu_bju.v:809`）与 `ex2_pipe2_chgflw_vld <= bju_chgflw_vld`
> （`:895`）挂在**同一个时钟沿**，所以检测拍 T 那拍 IDU 还**没有**冻住 —— IR 里那条
> 错误路径指令会在 T→T+1 沿**写进 RAT**。它随即被 `iu_yy_xx_cancel` 杀掉
> （`ct_idu_id_ctrl.v:300` / `ct_idu_ir_ctrl.v:907` / `ct_idu_is_ctrl.v:965`，当拍把
> ID/IR/IS 的 vld 清 0），**留下的 RAT 残迹正是由 BE 的整表覆盖收掉的**
> （这也是 BE 必须做整表覆盖、而不能只清队列的原因之一）。
>
> ⇒ 两条结论：① 冻结消掉的是"重定向到退休之间**每一拍**都在改名"这个**窗口**，
> 不是某一个具体的那一拍；② **D13 之后 BE 的整表覆盖仍然必须做**，它兜的正是这条边界。
> （复核声明这条是时序推断、未跑波形坐实 ⇒ **我们接上后值得用 VCS 抓一次波形确认**。）

> 📌 **顺带记下 `FLUSH_IS` 到底冲了什么**（我们将来做发射队列时要照着做）：
> 它的消费端**全在 IDU 里**、**不含 IFU 任何队列** —— 冲的是
> ① **发射队列条目本身**（`ct_idu_is_aiq0_entry.v:879-880` 的 `vld <= 0`，BIQ/LSIQ/SDIQ/VIQ 同型）
> ② 条目内的依赖/ready 记分板 ③ 已发射停在 RF 读出级的指令
> ④ IS 流水寄存器与发往各队列的 dispatch 使能。
> **已进执行流水的错误路径指令 `FLUSH_IS` 管不着**，是 BE 那拍由 `rtu_yy_xx_flush` 清的。
> 本核阶段 1 没有发射队列，等价物是 `rtu_backend_flush`（冲 ID_EX 往后）——
> 所以第 4 条改动**绝不能顺手把 `rtu_backend_flush` 一起删掉**（见下）。

#### 本核要改的五处（都是加法，不动 D2/D3）

1. **BEU → RTU：一根 `beu_redirect_vld`**（= `mycpu.v` 的 `iu_ifu_chgflw_vld`，
   执行级发重定向那拍告诉 RTU 一声，§6.1 新增，本计划内部信号、不进跨人契约）；
2. **RTU：一个锁存的"未决快路重定向"位 `mispred_pend`**（在 `RTU_flush` 里），
   与 `flushing` 一起进 `rtu_disp_stall`，在 `flush_lvl`（T+1）清。
   ⚠️ **必须是寄存器**，否则 P8 的"只依赖寄存器"就破了（C910 同样是寄存器：
   `if(bju_chgflw_vld) idu_mispred_stall <= 1;`）。
   **清优先**（保证一定能解锁）；活性靠"`beu_redirect_vld` 只由确实误预测的分支产生
   ⇒ 它退休那拍必然 `mispred_hit` ⇒ 必然有一次冲刷跑到 `flush_lvl` 来清"；
3. **`RTU_flush.v`：误预测时不再拉 `rtu_ifu_flush` / `rtu_ifu_chgflw_vld`**
   （陷阱/中断/mret 照旧）；
4. **★ 把 `redirect` 的两重身份拆开**（实现时才发现的，勘误补在这里）：
   `mycpu.v` 原来是 `wire redirect = rtu_ifu_flush;` —— **一根线同时干"核内冲刷"
   和"重启前端"**。D13 让这两件事对误预测取值不同，所以必须拆：
   * 新增 RTU 输出 **`rtu_core_redirect`**（= 退休拍的 `flush_trig`，**四类源都算**），
     `mycpu.v` 的 `redirect` 改由它驱动 —— 它管冲 IF_ID/ID_EX/EX_MEM、
     **按掉 store 写使能**（`mem_ram_we & ~redirect`）、CSR 静默、训练门控、掐同拍的 EX 重定向；
   * `rtu_ifu_flush` / `rtu_ifu_chgflw_vld` 只留给前端。
   ⚠️ **合成一根的症状是"错误路径的 store 写进内存"**（`~redirect` 失效），不是慢。
5. **门控按 D12 改成"年龄比较 + 提前一级锁存"**（阶段 4a-①，本次不做）。

#### ⚠️ 改完必须重新想清楚的一件事

现在"误预测退休时冲 IFU"**顺带**把错误路径上取的东西清了。改完之后从执行级重定向那拍起
前端取的都是**正确路径**，所以**不清 IFU 是对的**；但**后端（ID_EX 往后）以及 IDU 里
那几条更年轻的指令仍然必须冲掉** —— 冲它们的是 F1 的 `rtu_backend_flush`，
与 IFU 那两根信号是分开的，别一起删掉。

#### 为什么不干脆上快照（2026-10-02 实测参考核那条路线的代价）

参考核用 4 份检查点（`rename.v:97-102`：`rat_snapshots[0:3][0:31]` 32×6 +
`head_snapshots[0:3]` 6 + `mask_snapshots[0:3]` 4）换来"重定向当拍就恢复 RAT、
**不冻结**"，纯快照 **808 位**触发器（含掩码/snap_id/指针约 1344 位）。但它的

```verilog
// rename.v:144
assign stall_o = (free_cnt < req_regs) || (req_snaps + active_snap_cnt > 4) || stall_flag_i;
```

—— **在飞未提交分支超过 4 条就把整个前端冻住**，直到最老那条提交。64 项 ROB 根本用不满。

⇒ 按 D3（不做快照）走：**用"冻 IDU 一个窗口"换掉 808 位触发器 + 一条新的停顿约束**，
而那个冻结在窗口里本来就近乎免费（上面第 2 条）。

> **若将来发现冻结窗口在乱序下太长**（分支深在 ROB 里、前面卡着一条 cache miss 的 load
> ⇒ 窗口拖很久），再回头上快照 —— **那是加法，不是返工**：接口位置（"谁能恢复 RAT"）
> 是一样的，只是恢复时机从 F2 提前到执行级。

**验收**：CoreMark 周期对基线，difftest 全绿 + 指令数不变；
Fmax 按 §4.2 的 A/B 流程测（本条**不在重定向链上加组合深度**，见 D12，所以不应有代价）。

## 4. 微架构规格（参数表）

```verilog
// mySoC/rtu/rtl/RTU_define.vh  (或并入 mySoC/defines.vh)
parameter ROB_DEPTH   = 64;      // 表项数
parameter ROB_AW      = 6;       // log2(DEPTH)
parameter IID_W       = 7;       // ROB_AW + 1 位回绕
parameter DISP_W      = 3;       // 每拍派遣宽度 = 发射宽度
parameter RETIRE_W    = 3;       // 每拍退休宽度
parameter NUM_PREG    = 96;      // 物理寄存器数
parameter PREG_W      = 7;       // log2(NUM_PREG)
parameter ARCH_PREG   = 32;      // p0..p31 = x0..x31 初始映射, 永不释放
parameter NUM_LREG    = 32;
parameter CMPLT_PORTS = 5;       // ALU0/1/2 + BEU + MUL/DIV/LSU 汇总
parameter FLUSH_LAT   = 1;       // 冲刷状态机拍数 (2026-10-02: F1/F2 合成一拍, 见 D11)
```

**不变量**（写 RTL 时当断言用）：

1. `create_ptr - pop_ptr (mod 64) = 在途表项数`，范围 `[0, 64]`。
   **判满不要用指针比较，用计数器**：C910 是 `rob_entry_num[6:0]` 计数器，
   且**留 3~4 个空位**就置 `full`（`ct_rtu_rob.v:4471-4488`）——
   因为一拍最多要派 3~4 条，必须保证它们有位置。本核 3 宽派遣同理留 3 个空位。
2. 自由 preg 数 = `popcount(preg_state == FREE)`。
   **`FREE < 本拍要分配的个数` 时必须停重命名** —— 这是"死锁而不是变慢"的那类约束。
   参考核 free_list 只有 32 项却配 64 项 ROB，**在途写寄存器指令被压在 32**，
   64 项 ROB 根本填不满（`refcore` 独立复核确认了这一条）；
   要往 CoreMark 上跑之前，先加一条**上电自检打印**：`FREE 数 == 0 且还有指令在途`
   就 `$display` 报错，否则症状是"跑着跑着不动了"。
3. 表项 `vld=1` 的 `iid` 必须唯一（回绕位保证）。
4. 任一拍里 `preg_state` 的 `ARCH` 项数 == 32（每个 lreg 恰好一个）。
   这条适合做仿真断言，不是综合逻辑。
   > ⚠️ **2026-10-02 修正**：这一条**只在"初始映射被顶掉就回收"时成立**。
   > 现行 RTL 的 `old_preg >= 32` 门控让 `p0..p31` 永不回收 ⇒ 阶段 2 一开
   > ARCH 就是 `32 + K`，探针会误报。**先看 §10 的 D1.2 与 D3 再决定口径。**
   >
   > ✅ **2026-10-02 同日结清**：D1.2 选了"照 C910 回收初始映射"⇒ **本条目原样成立**，
   > 探针与断言都不用改。前提已由等价 TB（"`st[31:0] ≡ ARCH` 破坏 0 次"）与单元台
   > （空闲计数改数全表后连续自洽失败 0 次）逐拍核过。

| P3 | 96 位三端口优先编码 → preg 状态更新 | ★★ | **D2 的 `WF_ALLOC`**：切成"选择 / 派遣确认"两拍 |
| P4 | 5 路完成总线 → 64 项 × 7 位比较 → 置 `cmplt` | ★ 浅 | 一级相等 + AND-OR；影子表项另加 3 个比较器 |
| P5 | 3 路退休 → AMT 三写口 + `old_preg` 释放比较 | ★ 浅 | 寄存器直出，无长链 |
| P6 | 冲刷状态机 → 全表清 + RAT 224 位广播 | ★ 浅 | 一拍广播，无级联 |
| P7 | 派遣 → 表项写（独热指针译码） | ★ 浅 | **用独热指针**（C910 做法）：省掉 6 位加法器 + 译码器 |

**RTU 自己的落点（2026-10-02，阶段 1 落地后逐条对着 RTL 核过）**：

* **P2 —— `iu_ifu_chgflw_vld = mispredict & ~redirect & ~rtu_beu_flush_chgflw_mask`**
  （`mycpu.v:897`）。这条 AND 正落在上面 ② 的 **434/500** 那个锥上，是本阶段
  **唯一**新增到 EX→前端 的东西。两个新增输入源都是浅组合：
  `rtu_beu_flush_chgflw_mask = beu_mask = flushing = flush_trig | ~idle`
  （`RTU_flush.v:76/66`；`flush_trig = trap_hit|int_take|mret_hit|mispred_hit`，
  `RTU_commit.v:197`）—— 四个 hit 都是**影子窗口（3 个寄存值）上的比较**，2~4 级；
  `idle` 是 FSM 状态寄存器。⇒ **与 D12"末级只多一级 AND、输入同时到达"的预期一致。**
  **本阶段暂不改**，点名留给外跑判定（若 5.6 ns 点掉下来，先看这一条）。
  （D12 的门控那一级要等阶段 4a-① 才加，本阶段还没进这条链。）
* **P8 —— `rtu_disp_stall → stall / flush_id_ex → IF_ID、ID_EX 的 CE`**
  （`mycpu.v:1384-1385`；`stall` 与 `flush_id_ex` **成对**拉，见 §7 阶段 1 的第 2 条接线经验）。
  四项 `rob_full | preg_short | csr_inflight | flushing`（`RTU.v:560`）
  **都不依赖"本拍判退结果"**：`rob_full` 是计数器寄存值、`preg_short` 是空闲计数寄存值
  （且阶段 1 里恒假，见 §7 读法 A 的表）、`csr_inflight` 是槽的 vld 寄存器、
  `flushing` 是 FSM 状态 ⇒ **P8 成立**。
  ⚠️ **D13 会给它加第五项**（"未决快路重定向"锁存位）—— 那一项**也必须是寄存器**，
  否则 P8 当场破掉。这是 D13 里反复强调"必须锁存"的原因。
  ⚠️ 它与 r3 削刀后绑定的 `ex_csr_op → U_ID_EX/*_reg/CE` **是同族**（同一个 CE 端），
  所以外跑看报告时，P8 那条路径要和 EX 控制锥**一起**看。
* **P1 —— 判退面对的永远是影子窗口**：`read_entry0/1/2` 三个寄存器值，
  64:1 mux 已按 D5 移出关键路径（阶段 0 就在里面，阶段 1 直接受益）。
  `read_entry0` 永不 pop、完成匹配只比 iid 低 6 位，两条也都照 D5 落了。

**三条通用原则**（都是 C910 用了、我们照抄的）：

1. **能用寄存器隔开就隔开**：`read_entry` 影子表项（P1）、`WF_ALLOC`（P3）、
   退休判决提前一拍预计算（C910 的 "compare retire inst iid before retire"）。
   多花的寄存器按时序约束是划算的。
2. **独热指针优先于二进制指针**：C910 的 create/read 指针是**独热 64 位寄存器**，
   靠 `{ptr[62:0], ptr[63]}` 旋转更新，天然给出每项的使能，没有加法器、
   没有译码器。（它的 pop 指针是 6 位二进制 + 现展开，因为那里不敏感。）
3. **退休级要用的字段宁可多存，不要在退休级现算**：`pc/target/chk/dst_preg/old_preg`
   一位不砍（它们就在 P1 链上）；**反之，不在退休级用的字段要果断抽出去**
   （§4.3 的 CSR 槽省了 1.5 Kb，还让 P1 少读 4 个字段）。
   **退休级是新引入的收敛点，判据永远是"这条字段在哪条路径上被消费"。**

**验收判据（可执行，不是口号）**：

```sh

vivado -mode batch -source synth/build_fmax.tcl -tclargs 5.6 impl
# 判据: WNS >= 0   ⇒ Fmax >= 183.9 MHz
```

1. **判据是"5.6 ns 点上 WNS ≥ 0"，对应 Fmax ≥ 183 MHz** —— 不是"差不多"。
   注意**余量只有 0.16 ns**：基线自己是 +0.163，所以这条判据等价于"一点都不能退"。
2. 掉下来就按上面的 P1~P8 表定位是哪条路径，**先改 RTL 再考虑放宽约束**。
3. **本机没有 Vivado ⇒ 每阶段的时序验收必须外跑**，本机只做"人工核对无新增同类长链
   + 功能回归"。阶段 1 / 3 / 4 各跑一次（阶段 4 预期是**变好**，见上面的 P2 说明）。
4. 若某一阶段确实必须牺牲，**先记下掉在哪条路径、掉多少**，再决定是否接受 ——
   不要静默放过（本项目历次 Fmax 攻坚的结论都归档在 `synth/reports/`，
   新报告请按 `r2`/`r3` 的格式新开一轮目录，写 `README_zh.md`）。

### 4.3 省资源清单（**在 §4.2 时序达标的前提下**按序做）

#### 4.3.0 反过来：面积该往哪花（2026-10-02，用户给定"面积可接受、性能优先"）

这一节原本只讲"省"。用户把口径换成"**跑分要高、关键路径要短、面积可以多花一点**"
之后，同一份数据要反过来读一遍，结论有一条很干净：

> **在 `mispredict → actual_npc → redirect` 这条链上，只该减、不该加；
> 该花的面积花在"不在那条链上"的地方。**

依据是 §4.2 ② 那张 gshare 的 500 条清单：**434/500 = 87% 就是误预测/重定向链本身**
（`ex_A_reg[13]` 361 条 + `ex_csr_op_reg` 73 条），而**整个 gshare 方向表只占 18 条
（3.6%）**。⇒ 这颗核上"关键路径要短"和"CoreMark 要高"是**同一件事**。

按这个判据排面积优先级：

| 优先 | 往哪花 | 为什么 | 代价 |
|---|---|---|---|
| **1** | **BTB 的容量/相联** | 方向表之上更大的账（`ifu2-coremark-btb-lever`：单位比特收益 ≈ TAGE 表的 90×）；且**不在绑定路径上** | 基本不碰时序 |
| **2** | **gshare 表大小 / 索引质量**（GHR 宽度、PC 折叠） | 同上；BHT 只占 18/500 | 基本不碰时序 |
| **3** | 修**类 3 的 "word 索引不随相位分开"** | 那是**索引 bug 不是容量问题**（`bp-class3-root-cause`），修它不花面积 | 零 |
| **4** | 4a-① 的门控（D12） | 它是**加**在重定向链上的东西 —— 所以必须"提前一级锁存"，把组合深度消掉 | 一位寄存器 |
| ❌ | **不要**为"消除重取"上快照 | D13 实测参考核：808 位触发器，且 `active_snap_cnt > 4` 就冻整个前端 | — |

⚠️ 另有两条来自本项目实测的**纪律**：
* **容量类问题不要信 CBP 代理**（`proxy-wrong-way-t0`：代理说 T0 越大越好，CoreMark
  说无效甚至有害）—— 加 BTB/表容量只能看 CoreMark；
* **训练搬退休点（4b）不是面积问题也不是时序问题**，是正确性（§7-4b）。

## 6. 对外接口契约

> 📌 **这一节是交接契约，写给做重命名级的同事（以及写发射队列的人）。**
> 它可以独立阅读：你不需要看本文其它 900 行，只要按这里的端口和时序约定实现，
> 两边就能接上。有疑问的地方**先在这里改，再动 RTL** —— 契约漂移的代价是两边返工。
>
> 📌 **同一份契约在 `mySoC/rtu/rtl/RTU.v` 的模块头上还有一份"逐端口"的版本**
> （2026-10-02 补全）：每个端口一行注释，并标出它属于哪条约定
> （A1/A6b/A6c/A6d/A7/A8/D13）。**那个文件才是接线时手边的东西** ——
> 本节是"为什么"，那边是"这一根线要接什么、什么不能接错"。
> 两边冲突时以本节为准，并**同时改两处**。
>
> **谁负责什么（一句话版）**：
> * **重命名级（你）**：维护投机映射表 RAT、源操作数映射与旁路、算出每条指令的
>   `dst_preg`/`old_preg`，并在收到 `rtu_ren_flush` 时**用 `rtu_ren_recover_map`
>   整表覆盖自己的 RAT**。你不需要知道 ROB 有多深、退休窗口有多宽。
> * **退休单元（本计划）**：表项分配与回收、物理寄存器自由池与三态维护、
>   架构映射表 AMT、异常与冲刷裁决、提交点副作用（store/CSR/difftest/instret）。
>   它**不碰你的 RAT**，只在你该覆盖时给你一份完整映射。
> * **交界处的硬约定**（下面每条都有对应小节，别漏）：
>   1. **派遣必须等 `rtu_disp_stall == 0`**，一拍最多 `DISP_W = 3` 条，
>      且**必须是程序序的前缀**（允许少于 3 条，不允许跳号）。
>   2. **物理寄存器是"两拍分配"**：本拍你从 `rtu_preg_alloc_*` 看到的编号，
>      下一拍派遣时才真正落到 `ALLOC` 态（`WF_ALLOC` 打拍，见 D2）。
>      所以**同一拍内不要把刚拿到的编号再用于另一次分配**。
>   3. **`old_preg >= 32` 才需要释放**；`p0..p31` 是 x0..x31 的初始映射，永不回收。
>   4. **冲刷时你什么都不用算**：收到 `rtu_ren_flush` 就把整张 RAT 换成
>      `rtu_ren_recover_map`（32×7 bit），然后在 `rtu_disp_stall` 放开之前不要派遣。
>      不需要快照、不需要历史 —— 这份映射表只反映**已退休**的映射。
>   5. **`x0` 不分配、不映射**：`dst_lreg == 0` 时 `disp_dst_preg` 与 `disp_old_preg`
>      都是 don't-care，RTU 侧按 0 处理。

> ⚠️ **端口风格已定案（2026-10-01）：扁平编号，不用 SV unpacked array。**
> 本节最初的版本写的是 `input [6:0] disp_pc[DISP_W]` 这类端口。改掉的三个理由：
> ① `mySoC/**` 递归 grep，这类端口**一处先例都没有**；② 蓝本 C910 自己也是扁平编号
> （`rob_create0_inst_pc` / `rob_retire_inst2_cur_pc`）；③ 本核的 Fmax 验收要在 Vivado 上过，
> **不该拿一个新语法当第一次综合实验**。所以三路派遣 / 三路退休 / 五路完成一律写成
> `xxx0/xxx1/xxx2`（`xxx0` = 程序序最老的那条），与前端已有的 `idu_inst0/1/2_*` 同风格。
> 位宽与语义一位没变，只是把数组拆成编号端口。

### 6.0 物理寄存器分配握手（**重命名级最先要看的一段**）

preg 自由池与优先编码器**在 RTU 侧**（D2），所以是"你要、我给"，不是"你选、我记账"：

```verilog
// 重命名级 → RTU：本拍需要几个新 preg（每拍最多 DISP_W 个）
input  [1:0]  ren_preg_req;                 // 0..3
input  [4:0]  ren_preg_req_lreg0;           // 与"第 0 个请求"对应的 dst 逻辑寄存器（判 x0 用）
input  [4:0]  ren_preg_req_lreg1;
input  [4:0]  ren_preg_req_lreg2;
// RTU → 重命名级：给出去的编号（两拍语义，见下）
output [6:0]  rtu_preg_alloc0;
output [6:0]  rtu_preg_alloc1;
output [6:0]  rtu_preg_alloc2;
output        rtu_preg_alloc_vld0;          // lreg==0 的那一路给 0（x0 不分配）
output        rtu_preg_alloc_vld1;
output        rtu_preg_alloc_vld2;
output [1:0]  rtu_preg_free_cnt;            // 剩余可用数（< 请求数时你自己别发请求）
```

**车道语义（写死，别推导）**：`ren_preg_req = n` 表示**车道 0..n−1 是本次的请求者**，
车道 n..2 的内容是 don't-care。某条请求的 `lreg == 0` 时 RTU 给它 `alloc_vld = 0`
且编号 don't-care —— **不要**因为"车道被跳过了"就把后面的请求往前挪。

**时序语义（照 D2 的 `WF_ALLOC` 两拍）：**

| 拍 | 发生什么 |
|---|---|
| T | 你拉 `ren_preg_req`；RTU 做 96 位优先编码，把选中的 preg 置 `WF_ALLOC`，**同拍**把编号放到 `rtu_preg_alloc` |
| T+1 | 你拿这个编号更新自己的 RAT、随指令下发；RTU 在派遣确认那拍把它推到 `ALLOC` |

⇒ **`rtu_preg_alloc` 是"给下一拍用的"**，不要在同一拍里拿它去更新 RAT 再组合出
`disp_*`（那样会把优先编码器串进派遣链）。RTU 会保证这个编号在 T+1 拍仍然有效。

### 6.1 输入

```verilog
// —— 派遣（来自重命名级 / IDU）；k = 0/1/2 = 程序序 ——
input        disp0_vld;               // 允许少于 3 条，但不许跳号（前缀）
```

### 6.3 时序与边角约定（写 RTL / 写 TB 时按这个自查）

**① 冲刷时间线**（T = 触发拍。⚠️ **2026-10-02 改成 2 拍：原 `FLUSH_LAT = 2` 的 F1/F2 已合成一拍**）

| 拍 | FSM | 动作 / 可见信号 |
|---|---|---|
| **T** | IDLE→F1 | 退休窗口照常出信号（陷阱那条也在内：`dbg_commit_vld=1 / ena=0`）；**`rtu_disp_stall=1` 与 `rtu_beu_flush_chgflw_mask=1` 从这一拍就起**；`rtu_core_redirect=1` |
| **T+1** | F1 | **后端冲刷与重命名恢复同拍**：`rtu_backend_flush=1`（冲发射队列/执行级/存储队列）+ 清 `expt_entry.vld` + `rtu_ren_flush=1` / `rtu_ren_recover_vld/map`（AMT 整表）+ 所有 `ALLOC/WF_ALLOC → FREE` + ROB 三指针复位 |
| **T+2** | IDLE | `rtu_disp_stall` 放开 —— **早于此不得再派遣**（D3.1 的前提③） |

> 📌 **为什么能合**（2026-10-02 实测促成，见 D11 与 §7）：AMT 在**触发拍 T**（退休边沿）
> 就写好了，所以"恢复用的那张表"在 T+1 已经有效；后端冲刷与映射恢复是**同一批寄存器的
> 写**，同一个边沿上不冲突。C910 的 `FLUSH_IS_BE`（管线已空就把两级并成拍）是同一个意思。
> **收益实测 1.48%**（11,605,305 → 11,432,931 拍）—— 因为"冻结几拍"正是阶段 1 那
> +4.66% 的主因（每多冻一拍 ≈ 每次冲刷多花一拍 × ~13 万次）。
> ⚠️ **消费者注意**：`rtu_ren_flush` / `rtu_ren_recover_map` 现在**比原来早一拍**出现。

**② `rtu_disp_stall` 只依赖寄存器**（P8）。ROB 占用计数、preg 空闲数、FSM 状态一律取**寄存值**，
不许把"本拍判退结果"组合进来（那会造出 `退休判决 → 派遣停顿 → 前端捕获` 这条新长链，
而 `IF_ID 捕获` 本来就在 500 条最差路径里）。代价是停顿晚一拍 —— 按 C910 留 3~4 个空位容忍。

**③ 门控不许串在重定向链上**（D12，2026-10-02 改口径）。门控是**年龄比较**
（"不比上一次已发出的重定向更年轻"），且**在 ID 拍算好、随指令锁进 ID_EX** ——
末级只多一个 AND 一位寄存器。旧版这里写的是"只做 7 位相等比较（对队头）"，
**那个口径是错的**（证据见 D1 末尾的结案）。
`RTU_iid_cmp`（年龄比较模块）在 RTU 内部仍给异常收集与中断掩码用。

**④ 异常收集口只有一路，仲裁规则是"老级优先"**（MEM > EX > ID）。被丢掉的年轻异常不会丢信息 ——
异常随流水逐级锁存，下一拍还会从下一级报到；RTU 侧只留最旧的一条。

**⑤ CSR 指令的完成与写回（最容易做错的一条）**：
* 它的 rd 值（= CSR 旧值）**退休当拍才产生**，所以 `rtu_csr_rd_we` 那一拍值才进物理寄存器堆，
  **它的 `cmplt` 不代表 rd 可读**；
* 消费方（阶段 3 的发射队列）必须把 CSR 的目的寄存器当"不可旁路、等退休写回"处理；
  阶段 1（顺序核）的等价做法：依赖在途 CSR rd 的指令在 ID 停到它退休；
* `rtu_csr_addr` **一个口两种用**：组合读（→ `csr_rdata`）与写地址同值。退休那拍的组合路径是
  `csr_rdata → rtu_csr_wdata → CSR 写口`，只对 CSR 指令成立，不在 P1 链上。

**⑥ 交付脉冲口径（不许改，改了 difftest 立刻失步）**：同步异常那条**发**脉冲（`ena` 强制 0）；
被中断 squash 的那条**不发**（`retire_cnt` 也不计）；`mret` 正常发。

**⑦ `rtu_retire_cnt` 是 `[1:0]`**（编码 0..3），不是 3 bit 宽。`int_pending` 拉高后退休宽度压到 1。

**⑧ 同一时刻只允许一条 CSR 在途**：`disp_stall` 里必须有这一项，冲刷时清掉。

**⑩ CSR 的新值在退休级现算**（`csr_rdata` 是组合读口的输出，地址由 `rtu_csr_addr` 给）：

```
csr_src   = csr_op[2] ? {27'b0, csr_imm} : rtu_csr_src_rdata;  // csrrwi 系列没有 rs1
csr_wdata = (csr_op[1:0] == 2'b01) ? csr_src                   // RW
          : (csr_op[1:0] == 2'b10) ? (csr_rdata |  csr_src)    // RS
          :                          (csr_rdata & ~csr_src);   // RC
rtu_csr_rd_wdata = csr_rdata;      // 写 rd 的就是"旧值", 三种 op 一样
rtu_csr_we       = (csr_op[1:0] == 2'b01)                      // RW 恒写
                 | (csr_op[2] ? (csr_imm != 0) : (src1_preg != 0));  // 与 Control.v 同口径
```

> 最后那行能这么写，是因为 **x0 恒映射到 p0**（复位时 `AMT[0]=p0`，且 `p0` 永不进自由池），
> 所以 `src1_preg == 0` 与"rs1 域是 x0"等价 —— 这正是 `Control.v` 里
> `csr_we = (csr_op==RW) || (rs1_addr != 0)` 那一条的退休级改写。

**⑨ 慢路冲刷**也要重定向前端**（A6 的落地，这一条是从"哪些指令会被杀"倒推出来的）**：
T 拍 `rtu_ifu_chgflw_vld=1`，`rtu_ifu_chgflw_pc` 按来源三选一 ——
陷阱/中断取 `csr_trap_vector`；`mret` 取 `csr_mepc`；**误预测退休取该分支表项里的 `target`**。

> ⚠️ **下面这段描述的是阶段 1 的形态，已被 D13 取代（2026-10-02）。**
> 保留它是为了说清"当时为什么这样做"，以及**改的时候不能连什么一起删**。
>
> 阶段 1 的做法：从 BEU 在执行级发出重定向（D1 的快路）到这条分支退休之间，前端已经
> 重启并派出了若干条**正确路径**的指令 —— 但它们**是拿着还没恢复的 RAT 改名出来的**
> （RAT 要到 FLUSH_2 才被 AMT 整表覆盖）。所以它们必须和错误路径一起冲掉，而冲掉之后
> 必须**从分支的真实目标重取**，否则这些指令会被静默跳过。⇒ 慢路不是"只冲后端"，
> 是一次完整的"冲干净 + 从目标重取"。**实测代价 +4.66% 周期。**

> **D13 的修法（已定案）**：在执行级重定向那一拍就把 `rtu_disp_stall` 拉高
> （新增 `beu_redirect_vld` → 一个**锁存**位），把"拿未恢复 RAT 改名"这个**窗口**
> 从"重定向到退休之间的每一拍"压到**只剩冻结生效的那个边界拍**
> （C910 实测就是这样：检测拍 T 那拍 IR 里那条仍会写进 RAT，随即被 kill，
> 残迹由 BE 整表覆盖收掉 —— 见 D13 的精度修正）。
> ⇒ 慢路退化成"只冲后端"，`rtu_ifu_flush` / `rtu_ifu_chgflw_vld` 对误预测不再发。
> 这就是 C910 的形态（`FLUSH_IS` 不碰 IFU）。
> ⚠️ 两条别删：**F1 的 `rtu_backend_flush` 必须留**（后端 ID_EX 往后 + IDU 里那些更年轻的
> 指令仍然要冲掉，那是另一根信号）；**BE 的 AMT 整表覆盖也必须留**（它兜边界拍那条残迹）。

**⑪ iid 必须随指令走完流水线**（2026-10-01 补，阶段 1 接线时才发现的一条硬约定）。
`cmplt_iid` / `resolve_iid` 是**按 iid 寻址**的，而 RTU 表项里**只存回绕位**
（D4：`iid = {wrap, 该项的固定下标}`），也就是说**编号只有分配者知道**。所以：
派遣那拍从 `rtu_disp_iid*` 取回编号 → 重命名级把它随指令锁进流水线 →
完成/解析那级用它报 `cmplt_iid` / `resolve_iid`。阶段 1 的落地是
`ID_EX` / `EX_MEM` 各加 7 位 `iid` 字段（本核的"伪重命名级"就在 mycpu.v 的 ID 级）；
阶段 3 的发射队列本来就要存 iid（唤醒/选择/完成比较全靠它），届时这条自动成立。

> ⚠️ **别用"从退休指针现推"绕过它**：顺序核里确实可以靠"MEM 那条就是 rptr+1"
> 这种位置关系现算，但它成立的前提是"队头每拍都能退" —— 而这个前提在本核
> **马上就要被打破**（阶段 1 的 store 队列 `sq_rdy` 就能压住队头，阶段 3 更是常态）。
> 一旦队头被压住而流水线照常前进，这个位置关系就静默错位，症状是"某个表项被
> 提前标完成 → 退休顺序错乱"，而不是报错。**编号跟着指令走才是与位置无关的写法。**

**⑫ `rtu_trap_cause` 是 5 位异常号，**中断位由消费者补**（2026-10-01 阶段 1 实战）。
`mcause` 的 bit31 是"中断/异常"标志位（`INTR_MTIP_CAUSE = 32'h8000_0007`），
而 §6.2 的 `rtu_trap_cause` 只有 5 位、装的是**异常号本身**。消费者这样拼：

```verilog
// int_take ⟺ "这一拍有 rtu_trap_vld 但没有交付脉冲"（§6.3 ⑥：取中断那拍 pop_n=0）
wire irq_taken = rtu_trap_vld & ~rtu_commit_vld0;
CSR.trap_cause_i = {irq_taken, 26'b0, rtu_trap_cause};
```
漏掉 bit31 的症状很隐蔽：**陷阱路径全对，只有中断进来的 `mcause` 少一位**
（`csrr x5, mcause` 读回 `0x00000007` 而不是 `0x80000007`），
要跑到"中断处理程序分诊"那一步才炸。

#### 阶段 1 的映射口径（2026-10-01 定死；动手前先读这一节）

上面的"每条指令'分到'的 preg 就是它自己，映射是恒等的"有**两种读法**，
后果差一个数量级，动手前必须选死：

* **读法 A（选定）**：阶段 1 **不重命名**。派遣时
  `disp*_dst_preg = disp*_old_preg = p_<lreg>`（`dst_preg` 就是 rd 自己），
  `ren_preg_req = 0`。四态表 / 自由池 / 优先编码器**全部惰性**（见下表）。
  "接上四态 preg 表"= **接线就位**，真正激活是阶段 2。
* **读法 B**：阶段 1 就让 RTU 的分配器真发货（`dst_preg` 来自池子、`old_preg`
  来自一份跟着 AMT 走的迷你 RAT）。这要求同时改寄存器堆（7 位 preg 寻址、
  12 个口）、源操作数映射、旁路、`old_preg` 的产生 —— 等于把阶段 2 的活提前
  做掉一半，而且和阶段 2 自己的措辞（"重命名级出 RAT、旁路、`old_preg`；
  **RTU 侧接上**优先编码分配与退休释放"）直接矛盾。

**为什么是 A**（按分量排序）：① 阶段 2 把"接上优先编码分配与退休释放"明确排在
自己那一阶段；A3 也写明本阶段的副产品是"**用伪重命名顶替真重命名**把 §6 跑通一遍"。
② 读法 A 下 §6.0 的握手仍然被完整走了一遍 —— `ren_preg_req` 恒 0、`rtu_preg_alloc*`
  无人消费，但端口方向 / 位宽 / 两拍语义全都得接对，这正是本阶段要验证的。
③ 读法 B 会把"端口接错"和"语义改错"混进同一轮，而本阶段的定位手段只有 difftest。

**读法 A 下四态表到底惰性到什么程度**（写 RTL 时按这个自查，别去"修"它）：

| 端口/机制 | 阶段 1 的实际行为 |
|---|---|
| `ren_preg_req` / 优先编码器 | 恒 0 ⇒ 没有编号进过 `WF_ALLOC`；`sel_oh` 恒 0 |
| `rtu_preg_alloc*` / `_vld*` | 恒 0 / 恒 0（无人消费；`alloc_vld` 由 `ren_preg_req` 门控） |
| `rtu_preg_free_cnt` | 恒饱和值 3（`free_cnt` 只要不被 kill 偏移就是 64） |
| `ret_free_vld` | 恒 0 —— `old_preg = lreg < 32`，被 `old_preg >= 32` 那道门控挡住 |
| `ret_arch_vld` | 每条写寄存器的指令都拉，但 `p_lreg` 已经是 ARCH，**幂等** |
| AMT | 每次退休写 `AMT[lreg] <= lreg`，**恒等**，不变量自动成立 |
| `preg_short` | `free_cnt < 0` 恒假 ⇒ `disp_stall` 只剩 `rob_full | csr_inflight | flushing` |

> ROB 只能由它自己的四类事件（异常/中断/mret/误预测）触发冲刷，**没有对外
> 冲刷口**。所以"只搬退休、不搬冲刷"会得到一个"错误路径照常退休"的核 ——

**接线时踩出来的四条（都已写进代码注释，这里留索引）**：

1. **阵列表项退休时必须清**（`RTU_ROB_entry.pop_en`）。原设计只靠指针绕圈，
   `vld` 于是变成"这一格被写过"而不是"这一格装着在途指令"；ROB 快排空时
   窗口的"补空"路径会把上一代的表项补进来 ⇒ **同一条指令退休两次**
   （现象：`trap.S` 的 `wait_loop` 里 `0x304` 被重复提交）。单测台原本看不出来
   （激励总让 ROB 半满），已补一条不变量 **5b**（阵列 vld ⟺ 在途区间）并
   **反向验证过**：把 `pop_en` 关掉，单测台立刻红。
2. **`rtu_disp_stall` 必须用"停前端 + 给 EX 灌气泡"那一对**（`stall` 与
   `flush_id_ex` 同时拉），**不能只拉 `stall`**。本核的 `stall` 语义是"保持
   ID_EX"，只拉它会把 CSR 指令**钉死在 EX**：走不到退休 ⟹ `csr_inflight`
   永不清 ⟹ 派遣停摆；而且 A/B 锁存块不认 stall，被钉住那几拍会把 `ex_rD1`
   冲成 0，连带后面那条 `csrr` 的旁路值也变 0（现象是"csrr 读回 0"，
   比卡死更难查）。
3. **difftest 的"沿"要与退休脉冲分开看**（见 §10.C 的 C3）：`debug_wb_have_inst`

**为什么"store 退休时写"不能按字面单独做（② 的现状）**：
`mySoC/sync_mem.v` 的读口语义契约第 2 条明写"**写穿透在本工程里不是优化，是正确性**"，
它同时兑现两件事：
1. **store→load 同址**：写口在 MEM、读口在 EX，两者**同一拍**比较 —— 紧接着 store 的
   那条 load 必须看到新值；
2. **store→store 同址**：后一条 `sb`/`sh` 的读-改-写必须基于前一条已经合并好的字。

把写口挪到退休拍（= 晚一拍），这两条同时失效：紧跟的 load 拿到的是旧值、`sb` 会把
前一条写进去的字节整段盖掉。要正确就得**同时**上存储队列 + 字节级旁路（load↔store
与 store↔store 都要），那是阶段 2/3 的规模 —— 阶段 1 单独做它只会是把一个**已经正确**
的设计换成"看起来更接近终态、实际错数据"的设计。所以本阶段**保持 store 在 MEM 级写**：
那四条门控（`~mem_exc_valid` / `~redirect` / 中断的 `~w0_store` / 误预测快路不进 MEM）
已经让它**精确**（48 个用例 + CoreMark 逐位一致都在这个形态下过的）。
`rtu_store_vld*` / `sq_id` / `sq_rdy` / `sq_stall` 那一组口本阶段按"永远就绪"接，

  误预测保留它们就等于"前端再重启一次"。

**4b. 训练搬到退休点**（RTU 侧）

> 📌 **先把它的账摆正：这是正确性改动，不是时序改动（2026-10-02 更正）。**
> 本节原来写"搬走 `ex_A → BTB 训练写口` 是本项目最大的一笔时序收益"，那是

* 把 `iu_bht_check_vld` / `iu_btb_update_vld` 那两条（`mycpu.v:908-936`）

#### ✅ 4b 已完成（2026-10-02），过程中推翻/补上了原计划的三处

**① "`iu_chk_idx` 与 `iu_btb_chk` 的驱动源要改" —— 后半句是错的，会打断 D13。**
`iu_btb_chk` / `iu_btb_taken` / `iu_btb_is_cond` 在 ifu2 里是**双身份**的：
除了喂 BTB 训练，还要在**重定向当拍**现算 `ghr_restore`
（`rv32ifu2_top.v:740-742`）并打拍存 RAS 指针（`:768/781`）—— 而误预测重定向
发生在 **EX**，那三个必须是**当拍 EX 的值**。改成退休点驱动 ⇒ GHR/RAS 被修到
**另一条**指令的快照上（症状：一切正常，只是准确率缓慢变差）。
⇒ 实际做法是**拆端口**：新增一组 `rtu_train_*` 接口给训练，`iu_btb_*` 那三个
留在 EX 只服务修复路径。`iu_chk_idx`（只喂 BHT 的 `upd_ghr`）确实可以整体换源。

**② 表项缺 BTB 训练要的类型位。** `upd_cond/upd_jal/upd_jalr` 原来由 EX 从
`ex_npc_op/ex_is_jump/ex_is_jalr` 现算，而表项里只有 1 位 `is_branch`
（`RTU_define.vh`）⇒ **加 2 位**（`RTU_FLG_JAL/JALR`，表项 122 → 124，见 D4）。
另外**训练口还少一根 `target`**：BTB 的 `upd_target` 要真实后继 PC —— 原 §6.2
只列了 `pc/chk/taken`，那样根本接不上 BTB。两根都已补进 §6.2。

**③ BHT 必须只由条件分支训练。** 新的 `rtu_train_vld` 含 JAL/JALR，而方向表
**只**该被条件分支训练（JAL/JALR 没有方向，教它 "taken" 就是污染）。所以 BHT 的
`upd_vld` 接的是 `rtu_train_vld & rtu_train_is_cond` —— 搬走之前那条
`iu_bht_check_vld` 就是 `npc_op == BRANCH` 门过的，口径必须一致。
**这条不加整核 difftest 也发现不了**（只是预测器被带偏）。

**④ 顺带修掉的既有缺口**（单元台）：`rtu_ifu_train_*` 这一组**接出来之后一直
没人核**。4b 之后它是预测器的**唯一**训练源，所以单元台补了逐位守卫
（pc/chk/taken/target/三分类），并把影子窗口的逐字段比对扩到 `CHK` 与 `FLAGS`
—— **新加的类型位存得对不对，整核 difftest 守不住**（存错了功能仍对）,
只有单元台能守。补完当场就抓到一条真的：TB 自己的 `cp_flg` 还是 5 位，
把两位新标志截掉了（DUT 是对的）。

**⑤ ⚠️ 遗留：只有一个训练口。** 窗口里出现 2 条以上控制转移时，只有**最老**那条
被训练，其余**静默丢掉**（C910 是 3 个退休训练口）。1 发射的窗口最多一条分支 ⇒
恒等价、单元台也测不到；**3 发射落地前必须解决**，而且 IFU 侧 `u_bht/u_btb`
也只有单 `upd_vld` 口 ⇒ 这是**两头都要改**的活（RTU 加训练 FIFO 或按宽度节流 +
IFU 加口），列进"阶段 3 乱序落地"清单。

**⑥ ⚠️ 已知缺口：IFU=1 没搬。** `ifu_subsys`（C910 派生前端）还消费原来那组
EX 级训练网线，形状不同（`bht_check_vld/chk_idx`），没跟着改。

> 打一拍写进 BPU（`bpu_update_buffer.v`，那打一拍只是**时序**措施），而且

> 就照常产生 update。它现在没出事，仅仅因为"分支流水只有 2 级 + 单发射 ⇒
> 同一拍 EX 里只可能有一条分支，更年轻的在 RF 就被杀了"。
> **本核一旦把流水加深或多发射，这个洞就会漏**（错误路径的分支会训练预测器）。
> ⇒ 这是 4b 的又一条独立理由，而且它说明**别照抄 `bpu_update_buffer` 那种"只打拍不过滤"

### 8.2 difftest 必须同步改的两处（**容易漏**）

1. **`gm_check_step` 一拍要能喂多条**。现在 TB 每拍调一次（`tb_miniRV_dpi.sv:588`），

## 9. 风险与已知的坑

| # | 风险 | 说明 / 对策 |
|---|---|---|
| R1 | **自由 preg 耗尽静默卡死** | 参考核只有 32 个自由 preg，**在途指令上限被压在 32**（64 项 ROB 填不满）—— 它 CoreMark 跑不起来是另一个原因（`ret` 把 `ra` 读成 0），但"自由池见底 ⇒ 前端停摆 ⇒ 看起来像卡死"是本核必须防的。对策：不变量 §4.2 + 仿真断言 + 上电自检打印 |

| R3 | 物理寄存器堆端口暴涨 | 3 发射要 6 个读口 + 3 个写口 + **3 个退休读口**（difftest 要数据）。RegFile 是别的计划，但**端口预算现在就要按 12 口规划** |
| R4 | 内存接口时序 | 现在 MEM 级组合直出（`CORE_DESIGN.md §8.3`）。改成"退休时写"之后，store 的地址/数据路径与现在的转发逻辑完全不同，**要重画时序图再动手** |
| R5 | 位宽静默截断 | `ifu2` 的历史 bug：漏写 wire 位宽被截成 1 位、`25'd1 << 26` 恒 0。RTU 里 `chk`/`iid`/`preg` 全是窄位宽，**每个 assign 都要核位宽** |

**D1.2 自由池的有效深度是 33，不是 64** ★ 与 D3 是同一件事的两面

现状四处一起把 `p0..p31` 钉死：

| 位置 | 作用 |
|---|---|
| `RTU_preg.v` 复位 | `st[0..31]=ARCH`、`st[32..95]=FREE` |
| `RTU_preg.v` 的 `PREG_HI_MSK` + 前后缀树 | 扫描窗口只有 `[32,95]` |
| `RTU_commit.v:275` 的 `old_preg >= 32` | 被顶掉的初始映射**不放回池子** |
| `RTU_preg.v` 冲刷重算 `64 − arch_hi_cnt` | 写死"池子是 64 项" |

**后果**：每个"搬过家"的 lreg 会**额外留下一个永不回收的旧格子**。设 K = 现映射落在
高段的 lreg 个数（≤ 31，x0 从不写、恒在 p0），则可用池 = `64 − K`，程序跑开之后
**收敛到 33**。对照 §4 不变量 2 批评参考核的那句（"free_list 只有 32 项却配 64 项 ROB，
在途写寄存器指令被压在 32，64 项 ROB 根本填不满"）—— 我们收敛到同一个数。
顺序核里无所谓，**乱序恰恰要的就是深窗口**，所以这条在阶段 3 是一阶问题。

**C910 不是这么做的**：它的释放向量没有低段门控

⇒ 它的"32 个架构寄存器"不固定住 p0..p31，位置随改名漂移，池子恒 64、ARCH 恒 32。

**改法**（一条门控换写法 + 三处配套）：

```verilog
// 现在:  ret_free_vld = wr_eff & (old_preg >= 32)
// 改成:  ret_free_vld = wr_eff & (old_preg != dst_preg)
```

`dst == old`，这才是它存在的理由（去掉会让"转 ARCH"与"回 FREE"命中同一编号，
状态链保住 ARCH 但**计数器漂移**）。换成 `!=` 就**两个阶段都对**：阶段 1 恒假
（行为一位不变），阶段 2 恒真（`old` 来自 RAT 的活编号、`dst` 来自 FREE 池，必然不等）。
配套：`RTU_preg.v` 去掉 `PREG_HI_MSK`（扫描变 `[0,95]`，`PREG_BM*` 反而更简单 ——
不用再偏移 32）、冲刷重算改 `96 − 全表 ARCH 数`、`scripts/rev_mutations.txt` 的 **R01 重写**
（它现在断言的正是"低段不许回收"）。

#### D3. 不变量探针的口径要改（与 D1.2 同拍决定）

`tb/tb_miniRV_dpi.sv:129-134` 数满 96 项、要求 `ARCH 项数 == 32`；§4 不变量 4（`:818`）
同口径；§7（`:1619`）说它"要到阶段 2 才真正承重"——**这句话方向反了**。

按 D1.2 的现状（`p0..p31` 永不回收），阶段 2 一开 ARCH 就是 `32 + K`：例子见
"一条 addi x8 退休" ⇒ `p0..p31` + x8 的新映射 + x9 的新映射 = **34**，
第一次写 x8 退休探针就会报 `34 ≠ 32`。（`free_cnt` 那边反而是自洽的：
冲刷后 `64 − arch_hi_cnt` = 62，与真实 FREE 数一致。）

真正该守的是**两条结构性不变量**（与计数无关）：

1. `AMT[l]` 指向的每一项都必须是 ARCH 态（架构映射总是可恢复的）；
2. 不在 AMT 里的高段项，只能是 `FREE / WF_ALLOC / ALLOC` —— **没有"野 ARCH"**。

⚠️ **D1.2 与 D3 是同一件事的两面**：若采纳 D1.2（照 C910 回收初始映射），
> ✅ **2026-10-02 已随 D1.2 一起定案：走"回收初始映射"这条路，所以探针口径可以
> 原样保留**（`ARCH 恒 == 32` 重新成立，`tb/tb_miniRV_dpi.sv` 那条探针与 §4 不变量 4
> 都不用改一个字）。下面列的两条"结构性不变量"作为**备选**留着 —— 哪天改成
> 别的架构（例如池子不回收）再启用。
> 已机器核对的旁证：等价 TB 里"前提 `st[31:0] ≡ ARCH` 破坏 0 次" + 单元台新模型
> （空闲计数改数全表）连续 6 186 周期自洽失败 0 次 —— 两条合起来就是
> "ARCH 恒 32、池子恒 64" 在阶段 1 的逐拍证据。
`ARCH 恒 == 32` 会**重新成立**，探针可以原样保留；若不采纳，探针必须换成上面那两条。
选哪条路要一起定，不能只改一边。
